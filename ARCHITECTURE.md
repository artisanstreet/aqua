# Aqua architecture: pure core, native adapters

Last updated: 2026-11-04.

Implementation update (2026-11-03): the scene/protocol/runtime extractions,
explicit time and analytic springs have landed, together with text, native
Windows rasterization and full Editor application qualification in
[`docs/EDITOR_READINESS.md`](docs/EDITOR_READINESS.md).
The native host backend and render transport replacements below
remain the target architecture. The historical current-state descriptions
are not the latest feature ledger.

This document supersedes the foundation choices in `GUI_FRAMEWORK_DESIGN.md` (winit and wgpu) and records the target architecture. It is a design, not an implementation ledger: nothing below the "Current state" sections exists yet. Numbers marked "estimate" are unmeasured.

## 1. Goals

In priority order:

1. **Performance:** frame time, input latency, memory, idle cost, battery.
2. **Customizability on the level of a browser engine:** styles, effects, custom passes and themes without forking the framework.
3. **Text quality:** shaping, rasterization and editing that hold up next to native and Chromium text.
4. **Verifiability:** every subsystem deterministic, inspectable and testable without a window or a GPU.

Aqua is developed by agents. Engineering effort is not a constraint and verbosity is not a cost. API design buys explicitness, determinism and checkability instead of brevity.

## 2. Context: Rune

[anomalyco/rune](https://github.com/anomalyco/rune) is a Rust UI framework with similar goals. Its `PLAN.md` and `research/` folder (30 notes) were reviewed on 2026-10-29. Its motive is the author repeatedly hitting GPUI's architectural limits (no backdrop/glass, animation on the main thread, wrong window behavior for HUDs, thin text, no springs, a frozen upstream), plus code written and verified by agents. Its flagship test is recreating OpenCode Desktop.

Adopted from Rune:

- Animation runs on a render thread from analytic spring tracks; app code never runs per animation frame.
- A slow, obviously correct CPU reference renderer as the oracle for the fast GPU path, with differential tests.
- Text quality as a gated risk: pixel diffs against the native rasterizer.
- Perf measured by exact counts (allocations, instances, glyphs, layout nodes), so gates are bisectable.
- Pyramid blur with a fractional radius, closed-form shadows.

Where Aqua deliberately differs:

- **State.** Rune rebuilds view functions and diffs a keyed tree. Aqua keeps declared dependencies as data (`aqua-reactive`), which is the faster direction: invalidation cost follows what changed, not the view size.
- **Foundation.** Rune starts on winit and wgpu and drops to native only where measured. Aqua goes native from the start (sections 5 and 6).
- **Platform order.** Rune is Mac-centered. Aqua is Windows-first.

## 3. Principles

1. **Ports and adapters.** Pure crates define every boundary as traits and plain data (ports). Adapters implement ports and contain all OS and GPU code. Dependencies point inward only.
2. **Sans-IO core.** The pure runtime is a state machine: `step(Input) -> Output`. It reads no clock, spawns no threads and touches no files. Time, events and GPU results are inputs. Draw plans, window commands and wake deadlines are outputs.
3. **The pure side plans, adapters execute.** The core never says "call D3D12". It emits a `FramePlan` that is complete enough for a dumb backend to run.
4. **All `unsafe` lives in adapters,** except an audited `aqua-kernels` crate (section 4) where every kernel has a safe reference implementation.
5. **Capabilities are explicit.** Adapters report what they support. Unsupported features return errors, never silent no-ops. This continues the existing `EffectCapabilities` rule.
6. **Tiers change speed, never output.** A user on a weak laptop sees the same pixels as a developer on a flagship GPU, within the reference renderer's tolerances.

Differences from the first design: `aqua-ui` contains the keyed reconciler and the author-driven `MotionController` (`aqua-ui/src/motion.rs`, decided in 10.6); `aqua-motion` holds only `AppMotion`, `TrackSet` and the curves; `aqua-verify` is new; the legacy crates are deleted (`aqua-render`, `aqua-gpu-wgpu` and `aqua-platform`: window, geometry, monitor, badge, material and chrome types live in `aqua-protocol`; clipboard, notifications, dialog requests, open targets, taskbar badge, local time and preference queries live in `aqua-shell-win32`; image decode, animation and mesh data live in `aqua-media`; `decode_svg` does not render SVG text because `fontdb` is banned and `resvg` is built without `text`, `aqua_text::svg::outline_text` converts it to outlines first, see 14.E). No manifest, lockfile package or source path names `wgpu`, `glyphon`, `cosmic-text`, `winit`, `accesskit_winit` or `fontdb` (`aqua-verify` `banned`); the workspace manifest is `members = ["crates/*"]` plus shared package metadata.

### Enforcement

- `aqua-verify/tests/enforcement.rs` reads `cargo metadata` and fails if any pure crate depends on an adapter or on `windows`, `ash`, `objc2`, `winit`, `wgpu`, `glyphon`, `cosmic-text` or `fontdb`. `PURE_CRATES` covers all thirteen pure crates; a test compares the pure, adapter and host lists with the crate block above, and another requires the workspace members to equal the union of the policy lists. The `fontdb` edge through `resvg` no longer exists (14.E); the enforcement tests pass on Linux.
- `#![forbid(unsafe_code)]` on every pure crate except `aqua-kernels`; checked by the same test file.
- Pure crates do not call `Instant::now`, `SystemTime::now`, `std::thread`, `std::fs` or print; `lint_scanner.rs` greps for them and passes.
- Adapter facades are machine-checked in part: `ADAPTER_ROOT_ITEMS` in `policy.rs` lists every public item at each adapter's crate root, and `adapters_expose_only_declared_root_items` fails on any new or vanished root item, so widening an adapter surface is a reviewed policy change. `ADAPTER_PORT_IMPLS` requires `aqua-gpu-d3d12` and `aqua-gpu-ref` to implement `GpuBackend`, `aqua-ime-tsf` `ImeBackend`, and `aqua-transport` `RenderHost` and `Lowering`; adapters may not re-export a platform crate. Decision (round 6, loosened and recorded): the rule "nothing public beyond port implementations and a constructor" is not the enforced rule, because it cannot hold for the adapters as built. The host and the tests construct and drive adapters through concrete types and modules that are not port methods: `aqua-gpu-d3d12` publishes `hal`, `window` and `scene` (the host owns the `WindowBackend`, tiers, trim and recovery, which the `GpuBackend` port deliberately does not carry), `aqua-shell-win32` publishes `Window`, `clipboard`, `taskbar`, `dialogs` and the hooks the host installs, and `aqua-oracle-dwrite` publishes its DirectWrite types for the text diffs. The enforced rule is therefore the one in `policy.rs`: the public surface at each adapter's crate root is a reviewed allow-list (`ADAPTER_ROOT_ITEMS`, any new or vanished item fails `adapters_expose_only_declared_root_items`), the port implementations must exist (`ADAPTER_PORT_IMPLS`), adapters never re-export a platform crate, and pure crates never depend on an adapter. What is not checked is the signature of items inside public modules; a pure crate cannot reach them (the dependency test), only the host and `aqua-verify` can, so a widened module cannot leak into the pure layers.

## 5. The runtime loop

```rust
pub trait Machine {
    type Input;
    type Output;
    fn step(&mut self, input: Self::Input) -> Self::Output;
}

pub enum Input {
    Shell(ShellEvent),
    Ime(ImeEvent),
    Access(AccessAction),
    AccessClient { connected: bool },
    Gpu(GpuEvent),
    Render(RenderEvent),
    Tick(Instant),
}

pub struct Output {
    pub shell: Vec<ShellCommand>,
    pub ime: Vec<ImeCommand>,
    pub access: Option<AccessTreeUpdate>,
    pub render: Vec<RenderCommand>,
    pub wake_at: Option<Instant>,
    pub ime_area: Option<Rect>,
}
```

`aqua-protocol` defines `Input` and `Output` and re-exports them as `RuntimeInput` and `RuntimeOutput`; `Runtime` implements `Machine` over them. `Instant` is a plain value type in `aqua-protocol`, not `std::time::Instant`. `AccessClient` is an input so replay logs stay complete.

Consequences, all implemented:

- Recording inputs gives deterministic replay: `Recorder`, `replay` and `first_divergence` reproduce every output (`aqua-runtime/tests/runtime.rs`). Replay over the real host loop (with the render thread attached) is verified in `host_replay.rs`.
- Time control is `aqua_protocol::Timeline<M>`, a `Machine` wrapper over `Input`/`Output`: it maps host time onto machine time (`Pace::Running { rate }` for slow motion, `Pace::Paused` freezes `Tick` and `Frame` times while every other input still passes through), `advance(dt, windows)` steps a paused machine by exactly `dt`, and `seek(t)` rebuilds the machine from its factory and replays the recorded prefix (forward seeks replay the recorded suffix; a live input after a rewind discards the rewound future). `UiApp::record_session(window)` records every `RuntimeInput`/`RuntimeOutput` pair the host drives into that window's `Runtime`, including feedback from the render thread, so a live host session replays through a fresh `Runtime` or a `Timeline` (`aqua-verify/tests/host_replay.rs`).
- The headless mode and integration tests drive `step` with the reference GPU adapter and a scripted shell. `UiApp` is a thin wrapper over `Runtime` (it steps it with `RuntimeInput`), so the `todo` example's headless pump and the `aqua` tests drive the same state machine as the native host; there is no parallel pipeline and no `aqua_render` reference left.

### Threads

Two state machines, driven by the host, both defined in `aqua-runtime`:

- **App side:** `Runtime::step(RuntimeInput) -> RuntimeOutput`. Reactive flush, structural rebuilds, layout at the target state, text shaping, scene emission, input routing. Sends `RenderCommand`s (scene diffs, motion targets, uploads). Time enters only as `Tick` and `Frame`.
- **Render side:** `RenderSide::step(RenderInput) -> RenderOutput`, with `RenderInput { commands, feedback, present_at }` and `RenderOutput { events, frame, wake }` (`RenderWake::Idle | NextFrame | At`). It owns the presented scene and every motion track, and samples tracks at `present_at`. Sends `RenderEvent`s back (settled tracks, presented-frame ids, GPU timings, device loss and recovery).

Both are pure crates. The host owns the actual threads: the main thread runs the `aqua-shell-win32` message loop and `Runtime`; one render service thread (`aqua::render::service::RenderService`) drives every window: it owns one `RenderSide` and one `GpuRenderHost` (a `Lowering` over a handle to the shared `WindowBackend`) per window and builds them on that thread, because COM-backed backends are not `Send`. Messages cross a safe SPSC ring (`RenderCommand` one way, `RenderEvent` the other) and images cross on an `ExternalUpdate` side channel; a full ring drops a command and `RenderLink` keeps a backlog. Two further threads exist: the text prewarm worker (`persist::spawn_prewarm`, started once per process by `start_text_services`) and resource workers (`aqua::worker`). While one value animates, the app side does no work: verified for popups and scroll glide by the idle heap gates and the collections example's 0% idle CPU. Decision record: 14.3.

## 6. GPU port and rendering

### 6.1 The port

The planner is the hard part, so it stays pure and testable. The adapter receives a finished plan.

```rust
pub trait GpuBackend {
    type Error: std::error::Error;

    fn capabilities(&self) -> &GpuCapabilities;
    fn create_surface(&mut self, target: SurfaceTarget) -> Result<SurfaceId, Self::Error>;
    fn upload(&mut self, batch: UploadBatch) -> Result<(), Self::Error>;
    fn execute(&mut self, plan: &FramePlan, inputs: &FrameInputs) -> Result<FrameReport, Self::Error>;
    fn present(&mut self, surface: SurfaceId, hint: PresentHint) -> Result<PresentTimes, Self::Error>;
    fn recover(&mut self) -> Result<RecoveryReport, Self::Error>;
}
```

`FramePlan` is plain data:

- Ordered passes, each a `PassKind`: `Instanced { shader, instances }`, `Fullscreen`, `Compute`, `Copy`, `Custom`.
- Transient textures with size, format and a heap offset assigned by the planner (aliasing).
- Declared usage per pass (`reads`, `writes`). The planner derives barriers; the backend only translates them.
- Bindless texture handles by index, so no backend binding types leak inward.
- `ShaderId` plus specialization constants. Blobs come from `aqua-shaders` per backend.

Implemented shape (`aqua-graph`, `aqua-protocol`): authors build a `RenderGraph` (or feed `PaintCommand`s to `plan_paint`) and `RenderGraph::plan(PlanLimits)` returns a validated `FramePlan`. The planner culls instances outside the target or clip, culls passes that never reach the surface, hoists independent draws into earlier compatible batches, folds group opacity into instance alpha when children are disjoint, allocates transients by lifetime with first-fit aliasing, sets load ops (a transient's first write clears or discards) and derives transitions plus aliasing barriers. `validate` replays the barrier state machine, so a backend can trust the plan. Backdrop and content blur are graph nodes (`Copy`, a `BlurDown`/`BlurUp` pyramid of `Filter` passes, an `Images` composite) whose effective strength `offset * 2^levels` equals the radius, so animating the radius does not step. `GpuCapabilities::plan_limits()` feeds the planner. Layers (group opacity that cannot fold, rounded clips, content effects) are sized to their pixel-aligned bounds and drawn in layer-local coordinates (section 14.8); a layer that covers its whole target keeps the `LayerOver` composite, any other composites as an `Images` instance. A plan whose first surface use is not a clearing render pass (nothing writes the surface, or a backdrop read comes first) starts with an explicit clear pass: an empty `Instanced` pass carrying `LoadOp::Clear(plan.clear)`, so a backend never has to clear on its own.

The planner gets alignment, heap limits and feature tiers from `GpuCapabilities`. `FrameReport` returns timings, counters and device status as `Input::Gpu`.

### 6.2 Rendering methods

| Area | Method | Replaces |
|---|---|---|
| Common primitives | One instanced SDF "uber-quad": rounded and squircle rects, borders, gradients in Oklab with dithering, per-side soft clip edges | `rect.wgsl` per-rect SDF without gradients or dithering |
| Text | 8-bit glyph atlas with 4× horizontal subpixel positioning; Slug curve rendering for large, scaling or rotating text and icons | glyphon |
| Complex vectors | Sparse-strip or tiled path rendering for arbitrary paths | not supported today ("rounded-rect clips only") |
| Shadows | Closed-form erf blurred rounded rect in the fragment shader | `smoothstep` approximation |
| Backdrop blur | Downsample pyramid (dual Kawase or Jimenez) with a fractional radius, scissored to the element's bounds, as graph nodes | 9-tap Gaussian with integer downsample and step thresholds, which steps when the radius animates |
| Group opacity | Folded into instance alpha when children don't overlap; an aliased offscreen layer only when they do | always an isolated intermediate surface |
| Content blur, color matrix, custom effects, blend modes | Graph nodes, same mechanism as backdrop blur (`PushContentBlur`, `PushColorMatrix`, `PushCustomEffect`); displacement is not built, by decision: no workload needs it and `Custom` passes cover any later need | unsupported by decision |
| Rounded clips | `PushRoundedClip`: children render into a bounded layer that composites with a rounded clip (`ImageInstance::clip` plus `clip_radius`) | rounded-rect clips only through a stencil-less workaround |
| Damage | Per-swapchain-buffer age tracking with dirty rects passed to `Present1` | a retained full-window base texture |
| Custom effects | `CustomPassSpec` as data (HLSL source, inputs, outputs, bounds), compiled and cached by the adapter | `CustomPass` trait receiving wgpu types |

### 6.3 The D3D12 adapter

- `windows` crate bindings, Agility SDK runtime shipped with the app.
- DXGI flip-model swapchain with a waitable frame-latency object and tearing allowed. Frames start as late as possible against the waitable, which is the main input-latency lever on Windows.
- DirectComposition for per-pixel-alpha windows, popovers sized to content, and system backdrop materials.
- Placed resources in aliased heaps for render-graph transients.
- Shaders precompiled by DXC at build time. Pipeline state objects prebuilt, cached on disk and warmed at startup. The uber-shader keeps the PSO count, and the driver memory that comes with it, small.
- Device-removed recovery: the retained scene is enough to rebuild every GPU resource, so `recover` rebuilds and the app continues.

### 6.4 Hardware baseline and tiers

Most users run integrated GPUs or older discrete cards. The baseline must be fast there.

**Baseline (must run everywhere):** D3D12 feature level 11_0/12_0, Shader Model 6.0, legacy resource barriers. **WARP** (Microsoft's software rasterizer) as the last fallback for VMs, Remote Desktop and broken drivers.

| Feature | Baseline | Better tier |
|---|---|---|
| Binding | Small descriptor tables per pass, glyph atlas as a texture array | SM 6.6 descriptor heap indexing (bindless) |
| Barriers | Legacy transitions | Enhanced barriers |
| Uploads | Ordinary copy commands | Batched copies (`CopyBufferRegions`) |
| Sync | Queue-level fences | Fence barriers inside command lists |

What decides performance on integrated GPUs is memory bandwidth, not API features: damage-limited redraw, blur at reduced resolution, avoiding offscreen layers, zero work at rest, two-buffer swapchains.

### 6.5 DirectX update, October 2026

The Agility SDK 1.620 retail and 1.722 preview were announced on 2026-10-28. The raytracing work (clustered geometry, partitioned top-level acceleration structures, indirect builds) is in the preview and irrelevant to Aqua. Relevant from 1.620 retail, all as adapter-internal tiers:

- **Fence barriers tier 1:** signal and wait on fences inside a command list.
- **Batched asynchronous command list APIs:** independent copies that can overlap, clears without views and inside render passes. A fallback layer emulates them on older hardware.
- **DirectX dump files, driver-reported messages, extended PIX markers:** for device-removed debugging.
- **`CheckFeatureSupport1`:** capability queries clamped to an SDK version, a fit for `GpuCapabilities`.

On AMD, most require RX 7000 or 9000. Shader Model 6.10 goes retail in Agility SDK 1.621, due early December 2026.

### 6.6 Test hardware

Development machine: Radeon RX 9070 XT and Ryzen 7 9800X3D. The 9800X3D has a 2-CU RDNA 2 integrated GPU, usually set to "Auto" in the BIOS and therefore off while a discrete card is installed. Enabling it ("Integrated Graphics" set to Enabled or Forces, under Advanced, NB Configuration or AMD CBS → NBIO → GFX Configuration depending on the board) gives a pessimistic floor: it is weaker than typical laptop iGPUs but has laptop-like memory bandwidth. Select it with `EnumAdapterByGpuPreference` (minimum power) or by LUID. Presenting from it to a monitor on the 9070 XT adds a cross-adapter copy, which is fine for correctness and tier tests but skews latency. Measure with a monitor on the motherboard output or with offscreen benchmarks.

## 7. Shell, input, IME, accessibility

- **`aqua-shell-win32`** replaces winit. Win32 windows with per-monitor DPI v2, raw input, non-activating panels, custom chrome and drag regions (today's `chrome.rs`), system backdrop materials (Mica, Acrylic), clipboard, dialogs and OS preferences.
- **Shell surface (2026-11-04):** touch and pen arrive as `WM_POINTER*` and are translated by the pure `aqua_shell_win32::pointer::translate` into `PointerDown/Move/Up/Cancel` with a stable contact id (pointer id plus one; mouse stays 0) and per-contact button masks (pen barrel is `Secondary`, eraser tip `Extra(5)`); mouse stays on `WM_MOUSE*`, and pointer types other than touch and pen fall through to `DefWindowProc`. File drag and drop is an OLE `IDropTarget` registered per window and reported as `ShellEvent::FileDrag(Enter | Over | Leave | Drop)` with paths and logical positions. `aqua_shell_win32::set_message_hook` installs a `MessageHook`: `pre_translate` runs on every message before `TranslateMessage` (the TSF keystroke manager hook point; returning true consumes the message) and `window_message` runs first inside the window procedure and can answer a message itself. `WindowOptions::alpha_surface` creates the window with `WS_EX_NOREDIRECTIONBITMAP`, and `Window::attach_composition_surface` binds a composition swap chain (created with `DXGI_ALPHA_MODE_PREMULTIPLIED` through `CreateSwapChainForComposition`) to a DirectComposition visual, which is what lets Mica, Mica Alt and Acrylic show through; the GDI `present_bgra` path draws nothing on such a window. `WM_DPICHANGED` emits `ScaleChanged` first, then moves the window to the suggested rectangle (which emits `Resized`). The pure chrome hit test and geometry (`RectI`, `DragRects`, `HitInput`, `ht`), preference state (`PrefState`, `SystemPrefs`) and the material decision (`DwmSystemBackdrop`, `decide`) live in `aqua-protocol`; `aqua-platform` re-exports them and the shell no longer depends on `aqua-platform`.
- **`aqua-ime-tsf`** implements Text Services Framework directly. TSF loads on first text focus, not at startup. It is a pull-model `ITextStoreACP` over a windowed UTF-16 mirror of the focused text (`ImeCommand::Enable/Update` carry the window, selection and caret rectangle). TSF edits are translated into `ImeEvent`s (composition start/update/commit/cancel with byte cursors, plus `Replace` and `Select` for edits outside the composition); candidate windows are positioned from the caret rectangle in DPI-scaled screen coordinates; `ImeCommand::Reconvert` drives the system `ITfFnReconversion`. Composition that TSF wraps around programmatic edits is folded into a single insertion.
- **`aqua-a11y-uia`** implements UI Automation through AccessKit's Windows adapter (section 14.2). The host calls `UiaAdapter::apply(&AccessTreeUpdate)` with each `Output.access` and drains `UiaAdapter::drain_actions()` into `Input::Access`; the waker passed to `attach` must wake the host loop. It attaches only when a client connects. The accessibility tree is also the inspector's tree.
- **Shell file dialogs** pull many shell components and third-party shell extensions into the process, and they never unload. They run in a short-lived helper process.

## 8. Text

Text is a top priority. The pipeline is pure except font discovery.

| Stage | Choice |
|---|---|
| Discovery | `aqua-fonts-system`: system fonts memory-mapped, never copied into the heap; fallback scanned lazily with an on-disk index |
| Shaping | HarfRust (HarfBuzz port) |
| Paragraph layout | Parley or equivalent: bidi, line breaking, rich text, inline boxes, with a two-tier cache (shaped runs separate from wrap points) so resizing never re-shapes |
| Rasterization | skrifa outlines, luminance-based glyph dilation tuned against the native rasterizer, 8-bit atlas, 4× horizontal subpixel positions |
| Motion | y snapped to pixels and x to ¼ px while moving; Slug outlines for text under scale animation so glyphs never re-rasterize per frame |
| Editing | rope or sum-tree storage, today's `aqua-text` editor model on top |
| Gate | `aqua-oracle-dwrite` renders the same strings through DirectWrite; CI diffs per string at 1× and 2× |

DirectWrite is only loaded by tests. The look decision is closed in section 14.1.

### 8.1 Implementation (2026-11-04)

`aqua-text` no longer depends on cosmic-text, glyphon or wgpu. Layout is split into pure stages:

| Stage | Module | Notes |
|---|---|---|
| Discovery | `aqua-fonts-system` | Own scan of the Windows font directories (no fontdb): names, weight, stretch and style read through skrifa, CSS font matching; faces are memory-mapped once and shared as `FaceBytes` (the only `unsafe` in the text stack). Fallback is cmap-coverage driven per grapheme: explicit families, emoji families, platform script families, then a lazily cached scan. |
| Itemization and shaping | `shape.rs` | Spans split at font, bidi level and script boundaries; HarfRust per run with the span's features (ligatures off when tracking is set); `ShapedParagraph` holds clusters, runs and glyphs and is the tier-1 cache. |
| Line breaking | `lines.rs` | UAX 14 break opportunities from `icu_segmenter` (computed lazily per paragraph), greedy fit over clusters, hanging blanks, `Word`/`Glyph`/`WordOrGlyph`, tab stops, UAX 9 L1/L2 reordering per line, alignment and justification. This is tier 2: changing width, wrap or alignment never re-shapes (`TextLayout::reshape_count` is the exact counter). |
| Rasterization | `raster.rs`, `strike.rs` | skrifa outlines, exact-area coverage through zeno, 4 horizontal subpixel positions, y snapped, sizes quantized to 1/64 px, synthetic italic skew, fake bold (zeno stroke unioned with the fill, em/24 wide) when the requested weight is 600 or more and the face is lighter and not variable, COLR v0/v1 color glyphs (solid, linear, radial approximated; sweep approximated by its first stop), and CBDT/sbix bitmap strikes (PNG and premultiplied BGRA; nearest strike, area-averaged down or bilinear up to the requested size, placed from the strike bearings). |
| Atlas | `residency.rs` | `aqua-text` has no atlas of its own. `GlyphResolver` interns a face (font, weight, stretch, italic) to the `u64` in `aqua_media::atlas::GlyphKey`, rasterizes through `Rasterizer` on a miss and hands the bitmap to `aqua_media::Residency::glyph_any`, which routes masks to the 8-bit atlas and color glyphs to the RGBA atlas. `GlyphResolver::lower` turns a `LaidOut` into `GlyphInstance`s (masks) and `ImageInstance`s (color glyphs) ready for `glyph_passes`. |
| Tone | `aqua_graph::tone` (re-exported as `aqua_text::tone`) | The Microsoft grayscale contrast and gamma model as a pure function of coverage and text luminance (`ToneCurve::native()` is gamma 1.8, grayscale contrast 1.0). It lives in `aqua-graph` so `aqua-gpu-ref` and the D3D12 glyph shader share it without depending on the text stack. The pipeline blends in linear light while DirectWrite blends in sRGB, so `ToneCurve::linear_blend_alpha` also remaps the toned coverage so that a linear blend against the contrasting backdrop (black under light text, white under dark text) lands where DirectWrite's sRGB-space blend does. The HLSL (`glyph.hlsl`, constants in the root constants `region` and `values`) and the oracle implement the same function. |

Oracle results on the development machine (`aqua-oracle-dwrite`, Segoe UI, run natively on Windows):

- Shaping: glyph ids and advances equal DirectWrite's for five strings at 13, 16, 26, 32 and 48 px (worst advance delta 0.0000 px).
- Coverage: unhinted per-glyph coverage versus `CreateGlyphRunAnalysis` with grid fitting disabled has a mean absolute error of 2.9 to 7.3 levels (of 255) and an ink ratio of 0.98 to 1.01 at 13 to 32 px.
- Blending: with the tone curve, total ink versus `IDWriteBitmapRenderTarget` grayscale output (system parameters gamma 1.8, enhanced contrast 0.5, grayscale enhanced contrast 1.0) is within 0.94 to 1.05 (worst case 0.9425 at 13 px) for black, white, gray and colored text on light and dark backgrounds; without it white-on-black text is 20% light and black-on-white 13% heavy. A parameter sweep over gamma 1.0 to 2.2 and contrast 0 to 2.5 puts the optimum at gamma 1.9 and contrast 1.0 with mean error 11.039, against 11.046 for the system values, so the native parameters are kept.

- **Compatibility layer:** the `Application` trait (`aqua/src/runtime.rs`) is what the Editor port implements; the host extended it with `step_input`, `take_output`, `on_dialog`, `on_motion_event` and `motion_commands`. The port does not compile against it yet (`Input`/`Output`, `ExternalFrame` and the capture module changed).

## 10. Motion

### 10.1 Current state

`aqua-ui/src/motion.rs`:

- `Animated`: one property moving toward one target. `MotionKind` is `Tween { duration_secs, easing }`, `Spring(SpringParams { stiffness, damping })` or `Instant`.
- `MotionValue`: `Scalar`, `Pair`, `Color(Oklch)` with shortest-path hue.
- Retargets sample the displayed value first; springs keep velocity.
- Completion callbacks bind to a specific target; superseded completions are dropped and never fire.
- Reduced motion collapses in-flight and future motion to `Instant`.
- `MotionController`: generational arena of properties with owners (`NodeId`), `next_deadline`, `advance(now)`, `dispose_owner`.
- Time is always caller-supplied. It owns no clock.
- The controller lives in `OverlayHost` and advances inside `UiApp::build_frame` on the app thread. Authors reach it through `ui.host_mut().motion_mut()`.

Its semantics (no jumps on retarget, exact completion delivery, owner disposal, reduced motion, caller-supplied time) are already right for the new architecture. What changes is where it runs and how springs are evaluated.

### 10.2 Analytic springs

Springs are integrated with semi-implicit Euler at 1 ms substeps (up to 9,000 per sample on a clock jump) and channels are `Vec<f32>` (allocations per property). Replace with closed-form tracks:

A track is a segment `{ t0, x0, v0, target, params }`. With mass 1, `ω = sqrt(stiffness)` and `ζ = damping / (2ω)`. For the underdamped case, with `A = x0 − target`, `ω_d = ω·sqrt(1 − ζ²)` and `B = (v0 + ζωA) / ω_d`:

```
x(t) = target + e^(−ζω(t−t0)) · (A·cos(ω_d(t−t0)) + B·sin(ω_d(t−t0)))
```

The critically damped and overdamped cases have their own closed forms. Benefits:

- Exact position and velocity at any time, at constant cost, with no substep loop.
- Retargeting samples `(x, v)` at the presentation time and starts a new segment, so velocity carries over exactly as today.
- The settle time is computable, so the render side knows when a track ends without polling.
- The same formula can run in a shader for opt-in GPU-evaluated tracks.

`SpringParams` keeps stiffness and damping and adds a `duration`/`bounce` constructor (`ω = 2π / duration`, `ζ = 1 − bounce`). Channels become fixed `[f32; 4]` arrays: zero allocations per track.

### 10.3 Split across threads

`aqua-motion` splits into two halves:

- **App side (`MotionController`):** spawn, set target, policy, owners, completion registration. It does not sample. `set_target` emits a `RenderCommand::Motion` with the target, kind and the target's generation.
- **Render side (`TrackSet`):** owns segments, samples them at the display's target presentation time, writes presented values into property-tree nodes (transform, opacity, clip, colors, edges), and emits `RenderEvent::Settled { handle, generation }`.

Completion callbacks (`Box<dyn FnMut(Completion)>`) cannot cross threads, so they stay on the app side and fire when the matching `Settled` event arrives. A `Settled` event with a stale generation is dropped, which preserves today's "a superseded completion never fires" rule exactly.

### 10.4 Layout animation and presence

Layout runs once, at the target state. When a node's frame changes, the render side animates each edge that moved with its own track; stationary edges get no track and cannot jiggle. Shapes, borders and shadows are drawn at the presented size, so there is no scale distortion.

Presence: removing a keyed node with an exit motion moves it to an exiting state. It leaves layout flow, plays its exit and is disposed only when its tracks settle. A key that returns mid-exit revives from its presented state. `dispose_owner` keeps its silent-drop semantics and runs at that point.

### 10.5 Authoring motion

Today authors drive `MotionController` by hand. The builder API gains declarative motion: styles say what the value is, motion says how it gets there. When `render` reruns and a node's resolved style value differs, the runtime calls `set_target` on that node's track for that property.

```rust
const CARD: Motion = Motion::spring(SpringParams::SNAPPY);
const FADE: Motion = Motion::tween(0.12, Easing::EaseOut);
const ROW: MotionToken = MotionToken::new("row");

Box::new()
    .styles([ROW_STYLE, ROW_BASE, row_style])
    .animate(Animate::new().fill(CARD).border_color(CARD).frame(ROW))
    .presence(Presence::new().enter(FADE).exit(FADE))
    .build()
    .with_key(t.id)
```

Every animated property is listed explicitly; nothing animates by default and nothing animates on first mount. Motion values are `const` tokens in `aqua-style` (`Motion`, `MotionToken`, `MotionRef`, `MotionTheme`), so a theme can retune all motion in one place, and `MotionRuntime::set_theme` retargets in-flight token-referenced tracks live (literal motions are unaffected).

Implemented: `Animate` (opacity, fill, border_color, text_color, translate, frame) and `Presence` (enter, exit) live in `aqua-style/src/motion.rs` and ride on `Paint::motion`; `aqua-ui/src/motion/runtime.rs` (`MotionRuntime`, owning an `AppMotion`) diffs resolved values after layout and emits `set_target`; a node's first sight never animates, and `enter` applies only to nodes that arrive after the first reconcile. `aqua-layout/src/edge.rs` (`EdgeAnimator`) gives each moved edge its own track and none to stationary edges. Exit: `UiTree::sync_children` keeps a keyed node with an exit motion in the tree as an absolutely positioned, hit-test-excluded node at its last frame; `MotionRuntime::handle` removes it when every track it owns settles (the opacity track is always retargeted to 0, so a `Settled` event always arrives). A returning key reuses the node and retargets opacity from the presented state. Presented values exist only on the render side (`TrackSet`); `MotionRuntime` exposes targets and track handles, never sampled values, which is the app-side read rule.

The debug-mode read check is `aqua_reactive::read_check`: `render_scope(&deps, render)` panics in debug builds on any `ReadSignal::get/try_get` of a signal outside the declared tuple, naming its creation site (`#[track_caller]` on every signal constructor); `unchecked` exempts a region. `aqua-runtime::mount_reactive` and `ReactivePopup` wrap `render` in it. Host wiring (`aqua-runtime`): `Runtime::build_frame` calls `MotionRuntime::reconcile` after layout whenever the content, layout or viewport version changed, against the one `AppMotion` that `OverlayHost` also uses for popup and glide tracks (so track ids never collide), and `Runtime::step` delivers every `RenderEvent::Motion` to `AppMotion::handle`, `MotionRuntime::handle` (which finishes exits) and `OverlayHost::finish_popup_exits`. Tracks that `MotionRuntime` owns are spawned unbound; after scene emission the runtime resolves each `(node, property)` to scene items (`PushOpacity`, `PushTransform`, the fill, border and text items, and the shape items for edges) and sends `MotionCommand::Bind { track, binding, shift }`, or `Unbind` and `Bind` again when the mapping changes; `shift` is the ancestor scroll offset for edge tracks. `RenderSide` keeps a list of bindings per track and writes presented fill, opacity, border colour, text colour, translate and edge values into the scene items it owns. `UiTree::set_motion_groups` forces an opacity or translate group around nodes that animate those properties or have presence, so a node with no static opacity still has an item to bind. `PopupOptions::presence` fades a popup in and, on close, keeps its subtree mounted, non-hit-testable and fading until every exit track (opacity, plus translate when `Presence::slide(dx, dy)` is set) settles; with a slide, enter runs from the offset to rest and exit from rest to the offset on the same motion, and a closing popup is removed from the accessibility tree at once (`UiTree::set_access_hidden`, shared with exiting keyed nodes) rather than when its exit finishes. `RenderSide::step` reuses its sample, dirty and dedup buffers (`TrackSet::sample_into`), so a glide frame performs zero heap events (`aqua-verify` `render_allocations`), and `RenderSide::wake` reports `NextFrame` exactly while any track is unsettled. Verification: `aqua-verify` `motion_edges` sweeps layout-edge motion (plain and scrolled parents) and presence enter/exit at 60, 144 and 240 Hz against a 1440 Hz reference, plus jump and landing checks; `aqua-runtime` `edge_in_scroll` pins edge tracks in a scrolled ancestor, including a wheel notch mid-animation. Quad pulses and shimmer are render-thread cycles (14.N): they cost no app-side frames and no app wake. A binding that finds no item (for example a fill on a node that has none) is left unbound and the track still settles.

### 10.6 Slide, author-driven values, snapshot transitions (decided 2026-11-04, round 5)

**Keyed-node slide.** `Presence::slide(dx, dy)` now applies to keyed nodes as well as popups. `MotionRuntime` (`aqua-ui/src/motion/runtime.rs`) spawns a bound `Translate` track next to the opacity track: on enter it starts at the resting translate plus `(dx, dy)` and retargets to rest; on exit it targets rest plus `(dx, dy)` and joins the opacity track in the node's exit set, so the node is disposed only when both settle; a returning key retargets both tracks from the presented state. `MotionRuntime::groups` forces a translate group for any node with a slide so the binding has a `PushTransform` item. Tests: `aqua-runtime/tests/declarative_motion.rs` (enter, exit and revive, plus first mount not sliding). Verified through the real host loop (`Aqua`, `UiApp`, the render service, `OffscreenBackend` on WARP and the RX 9070 XT, readback of each presented frame): `aqua/tests/host_motion.rs` shows a keyed row sliding in over 15 to 16 presented frames from about 74 px to 0 and out to about 77 px with no step above 60% of the travel, a layout-edge animation moving only the right edge (101 to 299 in 13 to 14 frames, left edge fixed at 0 in every frame) and a popup slide (87 to 50 and back) across 11 to 15 frames.

**`MotionController` stays as the author-facing sampler.** The doc's app-side role (spawn, set target, policy, owners, completions, no sampling) is `aqua_motion::AppMotion`, which every runtime-owned property already uses (popups, glide, declarative animate and presence). `aqua_ui::motion::MotionController` is deliberately not rebuilt on top of it: it exists for values an author reads on the app thread to feed custom painting or layout, and a value that must be read back app side cannot be sampled on the render thread without a round trip every frame. It is not used by any runtime path, it owns no clock, and `OverlayHost::motion_mut` remains only for authors. Rejected: a facade that forwards to `AppMotion` and mirrors sampled values back through `RenderEvent` (one frame of latency on every read, and the declarative `animate` already covers the cases that do not need to read the value). The deviation from 10.3 is limited to this type; section 4's note is corrected accordingly.

**Snapshot transitions and text raster mode on D3D12.** Both are implemented in the host lowering, not in the backend, so the oracle and every adapter tier render them identically (`aqua/src/render/transition.rs`, `render/lower.rs`):

- `Lowering` keeps the previous frame's `PaintCommand` list (`clone_from` into a reused vector, so the vector itself is reused). `WindowRequest::Begin*SnapshotTransition` reaches the render thread as `ExternalUpdate::Transition(Settings)`; at the next lowering the retained list becomes the transition's snapshot. While the transition runs, the lowering appends `PushCustomEffect { spec } , <previous commands>, PopCustomEffect` after the new frame's commands. The custom pass (`aqua.snapshot_transition`, HLSL in `transition.rs`, a Rust twin registered on the oracle with `transition::register`) reads only the old frame as its input and outputs premultiplied `(1 - s) * keep_old * old + s * tint` with alpha `1 - (1 - s) * (1 - keep_old)`, so the ordinary Over blend onto the new frame yields exactly `(1 - s) * (keep_old * old + (1 - keep_old) * new) + s * tint`. `keep_old` and `s` follow the retired renderer's two modes: `SnapshotTransition` uses the soft diagonal reveal with a shimmer peaked at the edge, the two GPUI variants use the retired renderer's easing (a cubic Bezier solved for x with control values 0.65 and 0.35 and read at y with 0 and 1) and a near-hard edge with a smoothstep tint lobe. Rejected: copying the presented backbuffer into a texture (needs a new backend op in three crates and a barrier per transition start, and the replay of retained commands is exact and costs one extra scene walk for at most the transition's duration); a new `PassKind` (conformance work in the oracle, HLSL, planner and adapter for something the custom pass contract of 14.11 already expresses).
- While a transition is active `Lowering::transition_active` forces a `Plan::Full` repaint and `LowerReport::shimmering` is true so the render service keeps producing frames; the frame after `duration` carries no overlay and the report settles. Beginning a second transition during one restarts from the retained pre-overlay frame (the in-flight sweep is dropped, not nested). A zero duration, a band outside (0, 1] or a non-finite tint is rejected as `WindowError::Unsupported`; a window without a render link is rejected the same way.
- `TextRasterMode::Outline` sets a lowering flag that sends every glyph the slug store can hold through the Slug curve path (14.O) instead of the atlas; glyphs it cannot hold (color glyphs, fake bold) stay on the atlas. `PlatformDefault` clears it. Both arrive as `ExternalUpdate::TextRaster`.

Verified on Windows: `aqua/tests/transition.rs` renders old, mid-sweep, shimmer-peak and settled frames on the oracle, WARP and the RX 9070 XT and requires the three to agree within 6/255 (5 of 5 pass); `aqua/tests/host_motion.rs::a_snapshot_transition_crossfades...` runs it through the full host loop on WARP and the RX 9070 XT and sees the near edge turn new while the far edge is still old for 3 presented frames, ending on the new frame; `aqua/tests/windows_desktop.rs` (real native window) now has the three requests accepted instead of rejected. Not verified: the visual result in a real swapchain window under `win-app` (only offscreen targets and the native-window acceptance path were exercised), and the Editor's own theme-change call site. Known limits: a transition whose previous frame was already a transition frame shows the pre-overlay frame; transparent (composition) windows blend the tint with old alpha below one, which the soft mode approximates.

**Quad pulse and shimmer wake.** Decided (round 7, replaces the round 6 decision that kept them as frame-paced repaints with a wall-clock pulse): they are per-item analytic cycles owned by the render thread. `aqua_motion::Cycle` is the pure closed form (`Pulse { period, floor }`: `floor + (1 - floor) * (cos(2 pi t / period) * 0.5 + 0.5)`; `Sweep { delay, duration }`: 0 for `delay`, then 0 to 1 over `duration`, repeating) and `aqua_motion::CycleSet<K>` anchors each key on the first frame the render thread draws it (a pulse is keyed by its scene item id, a shimmer by its `key`), restarts it when its cycle parameters change, and forgets it on the first frame it is not drawn. The app's `start_ms` is no longer read, so a replay at the same presentation times gives the same commands (`aqua/tests/render/animation.rs`). The lowering reports `pulsing` and `shimmering` while any cycle is live; the render service then asks `FrameTarget::repaint()` for `Repaint::Animating` (a transition keeps `Repaint::NextFrame`), which schedules the next repaint `ANIMATION_PERIOD` (15 ms, so at most the 60 Hz class and at the display refresh on slower panels) after the previous one instead of on every vblank. An animation-only repaint is silent: it does not invalidate the damage baseline and its `Presented` feedback is not posted to the app, so the app thread does not wake, build or lay out for it (measured on the Editor landing screen: 161 app wakes per second before, 0 after). Damage is the footprint of the animated items only: `DamagePlanner` collects the world-space bounds of every quad inside a pulse scope and of every text run inside a shimmer scope (the shimmer's map bounds united with the run's ink), under any `PushTransform` stack, and records them as damage each frame; a frame whose damage touches a backdrop blur zone (blur bounds grown by twice the radius plus 8 px) is still `Plan::Full`, any other damage no longer is. `GpuFrames` asks the backend for the repaint region (`WindowBackend::repaint_bounds`, which includes the per-buffer age accumulation) before lowering and the lowering drops every leaf command outside it (`render::cull`: quads, gradient quads, shadows with their blur reach, images and backdrop blurs by bounds, glyph runs glyph by glyph; scope commands are kept so pushes and pops stay balanced; nothing is dropped inside a blur, colour matrix or custom-effect layer). Rejected: patching the retained command list per animated span (the walk is 0.09 ms of a 0.7 ms frame and the retained list would need span bookkeeping across run-cache hits), and making the cull part of `plan_paint` (aqua-graph has no notion of the repaint region). Verified on Windows (RX 9070 XT, release Editor port, landing screen with its status shimmer, same display at 165 Hz, `AQUA_PROFILE=1`): before, the render thread presented 164 full frames per second (`lower 0.10, plan 0.04, record 0.13, present 0.50` ms on average, p50 work 0.49 ms) and the app thread woke 161 times per second to receive `Presented`; after, 65 partial frames per second (`aqua-render-damage: full=0 partial=166 culled_commands=26062` per 166 frames in the intermediate 165 Hz run, so about 157 commands culled per frame), 3 app wakes per second (all from the Forge network and window requests), render thread 56 ms of CPU per second (`threads` probe), zero app frames. `aqua-verify/tests/host_animation.rs` asserts partial frames, culled commands, zero scenes sent and zero `Presented` events over one second; `aqua/tests/render/animation.rs` asserts the exact pulse values and byte-identical commands for equal presentation times on any wall clock; `aqua-motion/tests/cycle.rs` covers the closed forms; `render_service` covers the capped silent repaint. Not met: the 0.3 ms per frame target. A frame costs about 0.35 ms outside `Present1` and `Present1` itself about 0.5 ms of CPU in the AMD driver and DWM (`present` 0.39 to 0.50 ms average, 1.2 ms when paced at 15 ms), so the floor at the display refresh is about 0.85 ms per frame; the cap is what removes the cost (65 instead of 165 presents per second).

Measured on 2026-11-04 (see 11.1). The first-draft table was an estimate and underestimated the driver by an order of magnitude; the revised budget below is what the gates enforce.

Budget (enforced by `aqua-verify`): the offscreen renderer path on a discrete adapter, 2560x1440 BGRA8, the editor workload, adds at most 96 MiB of private bytes over the bare process (measured 72 to 78), a framework heap of at most 4 MiB, steady-state growth of at most 1 MiB over 600 frames, and at most 48 MiB of local video memory (measured 31.6). The windowed editor target is the offscreen figure (34 MiB Aqua-controlled: renderer 10, surface 15, caches 9) plus a second swapchain buffer (15), the application heap (about 4) and slack, 57 MiB, on top of the 83 MiB driver floor Aqua cannot influence (device 43, first `Present` 40): 140 MiB private on a discrete GPU. This is not half of the GPUI Editor: the GPUI Editor measures 74 MiB private (debug build, the only one prebuilt; section 12.3), so on a discrete GPU the D3D12 driver alone costs more than that whole process. The old claim of "half of 25 MB" is withdrawn; the budget that remains meaningful is the Aqua-controlled share, zero steady-state growth, and VRAM. The windowed swapchain path is gated by `aqua-verify/tests/window_memory_budget.rs` (`RENDERER_WINDOWED`: 140 MiB private over the bare process, 4 MiB framework heap, 1 MiB steady growth, 64 MiB local video memory; 2560x1440 swapchain, editor workload, 600 presents; measured on the RX 9070 XT, debug test build: 107 MiB private, 0.0 MiB steady growth, 48.7 MiB video memory, frame CPU p99 1.4 ms). The whole-application gate is `tools/compare-editors.sh`, which fails the run when the settled private bytes exceed 142 MiB or dedicated GPU memory exceeds 64 MiB and prints the GPUI comparison. Measure with a uniquely named executable per run (`win-drive.ps1` does): per-thread context-switch counters are keyed by process name, and a shared name mixes in unrelated processes (idle Aqua read 2600 switches/s that way, 9.5/s once isolated). Transients are aliased and sized to effect bounds (the planner sizes layer transients to their bounds, record 14.10, so a 200x40 px group costs 64 KB instead of 29 MiB; the D3D12 executor consumes that sizing, but no end-to-end windowed measurement exists); the atlas is an 8-bit texture grown in pages with eviction. The adapter responds to video memory budget changes and frees transient heaps when minimized.

Implemented residency (`aqua-media`, verified against `aqua-gpu-ref` on WARP and a hardware adapter): one `Atlas<K>` per texel format (8-bit mask for glyphs and single-colour paths, RGBA8 for images, SVG and gradient paths). Shared pages grow 256, 512, 1024 up to a page cap; items larger than a quarter of the maximum edge get a dedicated exact-size page. Allocation is shelf packing without a CPU mirror. When a budget or the page cap is hit, the least recently used page that holds nothing used in the current frame is reset (shared) or released (dedicated), so a page can never be overwritten while an earlier draw of the same frame still reads it; if every page is in use the atlas grows past budget and counts it. `trim_idle` releases pages idle for N frames (minimize, memory pressure), and the D3D12 side frees the matching `ID3D12Resource` behind the frame fence. Large uploads are split into row bands and streamed under a per-frame byte budget. Paths and SVG are rasterized on the CPU (tiny-skia, resvg) into the atlas, not rendered by a GPU path pipeline; Slug-style rendering for scaled text and animated paths is not built. After device recovery the host must call `Residency::clear` between frames (it drops every page, pending update, streaming queue and retained vector source, and bumps `Residency::generation`), and reset any `PageTable`; the next frame re-creates and re-uploads whatever it draws, so a recovered device never sees a release or write for a page it does not have. Glyphs go through `Residency::glyph_any`, which keeps the 8-bit mask and the RGBA color-glyph atlases apart.

Pure crates get an exact heap gate: `aqua_verify::heap::CountingAllocator` counts allocations, reallocations and bytes per thread plus live and peak bytes process-wide, and `HeapGate` fails a test on any excess. Gates in force (`aqua-verify/tests/heap_gates.rs`): an idle `Runtime::build_frame` performs zero heap events at 100, 1000 and 4000 rows and shapes, measures and emits nothing; an idle `RenderSide::step` with 10 and 5000 scene items performs zero heap events and requests no wake; `emit_scene_diff` of an unchanged 2000-item scene allocates nothing; a cold mount shapes each text run exactly once. The earlier `aqua` perf_scene failure (12 allocations per idle frame) does not reproduce on the extracted runtime.

Whole-host heap budget (decided in round 5, status note): the 4 MiB framework heap figure above is the renderer-side budget and stays the gate for `RENDERER_OFFSCREEN` and `RENDERER_WINDOWED`. The full host in `aqua-verify/tests/host_window.rs` (400-row document at 2560x1440, release) measured a 13.2 MiB framework heap, which includes the UI tree, layout, shaped text runs and the scene, and was gated by `HOST_WINDOWED` at 16 MiB with the other fields equal to `RENDERER_WINDOWED` (round 6 measured 9.5 MiB after the interaction-store fix and tightened the gate to 12 MiB, section 11.4) (140 MiB private, 1 MiB steady growth, 64 MiB video memory). This is a deliberate loosening of the original application-heap allowance (about 4 MiB) to a measured figure plus slack, not a claim that the 4 MiB target is met by the host; tightening it needs a per-subsystem heap breakdown, which does not exist.

The 4 MiB figure counts only renderer-side state (`RENDERER_OFFSCREEN`, `RENDERER_WINDOWED`). ### 11.3 GPU dedicated memory below the 64 MiB gate (round 6, 2026-11-04)

Measured with `AQUA_MEMORY_REPORT=1` and the `win-app` `gpumem` probe (perf counter `\GPU Process Memory(pid)\Dedicated Usage`) on the RX 9070 XT, landing screen of the Editor port, window client 1898x1125 physical, debug-profile port build (the allocations below do not depend on the profile), `AQUA_RENDER_WHEN_COVERED=1`. After 600 wheel steps over the sidebar the figure did not move (63.9 before, 63.9 after, two runs; 63.7 in an earlier build); the thread view with a large thread needs the benchmark fixture and was not measured.

| Step | GPU dedicated MiB | Evidence |
|---|---|---|
| Round 5 landing | 77.7 | breakdown in 11.2 |
| Composer glass without RGBA atlas pages (5 path pages and the avatars gone from the atlas) | 71.0 | atlas resident 6.9 to 0.8 MiB |
| Backdrop blur without snapshot and full-resolution output (transient heap 6.4 to 1.2 MiB) | 66.0 | A/B with the old planner path in the same build: 71.0 against 66.0 (the 3 level threshold was measured last: 63.9 with transient heap 1.2 MiB) |
| `Core` shader-visible descriptor heap 69,632 to 2,112 descriptors | 63.7 | `AQUA_SRV_STATIC=4096` alone gave 64.1 (-1.9 MiB); the production renderer never uses this heap, only the HAL tests do |

What was changed, in cause order:

1. The five glass paths (`ui/tab_card.rs` of the Editor port) were `GpuiPath` fills and strokes rasterized by resvg into one RGBA page each (5.0 MiB). They are now `GpuiBackground` and `GpuiBorder` items with per-corner radii: analytic quads and gradient quads in the existing quad pass, no raster at all. The shapes are an approximation of the old silhouette (tab, body, well, strip as rounded boxes); the Editor's UI fidelity is not a goal.
2. The planner no longer snapshots the target for a backdrop blur and no longer allocates a full-resolution output for deeper blurs. `BlurDown` may read the surface (`validate`: the surface may be read by a copy or by a blur down-sample, nothing else), so the first pyramid level samples the target directly. For `HALF_RESOLUTION_LEVELS` (3) levels or more the last up-sample pass is dropped and the composite image pass samples the half-resolution level bilinearly (`BlurOutput::texels` is the level's extent); the pyramid's offsets are scaled by `HALF_RESOLUTION_OFFSET_SCALE` (1.03) to give back the width the dropped tent contributed. Peak transient bytes per blurred region fall from about 10.7 to about 2.7 bytes per pixel (RGBA16F: snapshot 1.0, level 1 0.25, output 1.0 before). The two constants are evidence based, from `aqua-gpu-ref/tests/blur.rs` (`blur_width_grows_smoothly_and_monotonically_with_the_radius`, impulse width in pixels, largest step per 0.4 radius: limit 0.9): the previous planner 0.818; dropping the pass from 3 levels without compensation 0.948 (fails), because the 3 level blur ended 0.3 px narrower at radius 13.6 (11.12 against 11.41); with the 1.03 scale 0.839 (radius 13.6: 11.47, radius 8: identical to the previous planner at 7.6757, radius 16: 15.36 against 15.30). The Editor's glass blurs mix 3 and 4 level pyramids, which is why the threshold is 3 and not 4: with 4 the Editor held a 4.4 MiB transient heap, with 3 it holds 1.2 MiB. Below 3 levels the full-resolution path stays; mixed depths whose two pyramids differ in resolution mix at full resolution.
3. The `Core` HAL owned a 65,536 + 4,096 descriptor shader-visible heap on the Bindless tier that only tests allocate from; it is now 64 + 2,048 on every tier. The `Core` upload ring starts at 64 KiB instead of 1 MiB (system memory, not in the perf counter; the HAL tests grow it on demand).
4. The host now calls the backend's budget and visibility paths. `RenderLink::set_hidden` (raised from `WindowEvent::Occluded`) sets `RenderStats::hidden` and wakes the service; the slot calls `FrameTarget::visibility` before its next frame, which marks the window hidden in the shared hub and calls `WindowBackend::set_visibility(Hidden)` when every window sharing the device is hidden (transients and upload rings are released immediately, `evict_idle_resources` is returned) and `Visible` when any is shown. A true `evict_idle_resources`, from a hidden device or from `service_budget`, requests `TrimHandle::request`, so the next lowered frame runs `TrimRequest::Everything` and drops idle atlas pages, glyphs and Slug records on the render thread, where the residency lives. `service_budget` runs in the existing maintenance hook (every `MAINTENANCE_FRAMES` frames) and applies `trim_for(pressure, visibility)`. Tested in `tests/render_service.rs` (`hiding_and_showing_a_window_reaches_its_target_once_per_change`) and, for the backend half, `aqua-gpu-d3d12/tests/window/memory.rs`. The hidden path was not observed in a real occluded window: `win-app` windows are not covered by anything.

The target of 50 MiB, and any figure below the GPUI Editor's 53.6 MiB, cannot be reached on this driver with a D3D12 device, and no Aqua allocation is left that would close the gap. Raw measurements, a 1920x1160 window and a 1898x1125 B8G8R8A8 flip-model swapchain with two buffers, no Aqua code involved (probe built from `windows` bindings only):

| Stage | GPU dedicated MiB |
|---|---|
| process start | 0 |
| D3D12 device (feature level 12_0 or 11_0, same) | 42.6 |
| + command queue | 44.1 |

The D3D12 user-mode driver costs 28 MiB more than the D3D11 one at device creation, before any queue, heap or pipeline exists, and the swapchain adds 17.1 MiB. The floor of 61.1 MiB is above the GPUI Editor's total (53.6 MiB, D3D11) and above the 50 MiB target. Aqua is at 63.7 to 63.9 MiB, about 2.7 MiB over that floor: transient heap 1.2, atlas 0.5 resident, scene upload 0.2, the pipelines and the rest. ### 11.5 GPU dedicated memory above the D3D12 floor, and the D3D11 evidence (round 7, 2026-11-04)

Method. `compare-editors.sh` phase `memdiag` (release port on the bench fixture, `bench-large` open, 600 wheel steps 16 ms apart; `AQUA_STATS_OVERRIDE=memory` keeps `AQUA_MEMORY_REPORT=1`, so the host prints `aqua-gpu-memory` once per second next to the `gpumem` probe). After (same fixture, same machine, RX 9070 XT, release): 64.7 MiB after startup, 64.9 MiB after 600 scrolls; transient heap 1.2 MiB (blur pyramids only), no change in the heap over the scroll. GPUI on the same fixture: 49.1 and 51.1 MiB.

What a D3D11 adapter costs. (1) Code: a second `GpuBackend` next to `aqua-gpu-d3d12`, about 8,300 lines of Rust in `hal`, `scene` and `window` there, of which the device selection, swapchain, pacing, damage, mirror and recovery logic is largely reusable in shape and the command recording, barriers, descriptor management, transient placement and timestamps are D3D12 specific and would be replaced by immediate-context calls. (2) Tiers: D3D11 has one tier. Bindless (SM 6.6 `ResourceDescriptorHeap`), enhanced barriers, placed-resource transients, the shared descriptor ring and fence timelines do not exist; every pass binds its textures with `PSSetShaderResources`, so a D3D11 tier is `Baseline` without the other three axes, and `conformance` and `tiers` would run one variant, not four. (3) Shaders: `aqua-shaders` compiles every entry with `dxc` to DXIL (SM 6.x); D3D11 needs DXBC (`fxc`, SM 5.0), so `build.rs` gains a second profile and the 808 lines of HLSL must avoid SM 6 only constructs outside the bindless path (the bindless path stays D3D12 only); `CustomPassSpec` HLSL compiled at runtime would have to go through `D3DCompile`. (4) Oracle: nothing in `aqua-gpu-ref` changes, the conformance harness is generic over `GpuBackend`, and the new adapter must pass the same 133 cases and the differential fuzz with the same tolerances (the D3D12 adapter stays the reference for the tolerance work); the tests that are about D3D12 internals (heap gate, transients aliasing, debug layer, enhanced barriers) get no D3D11 counterpart, and the D3D11 debug layer takes their place. (5) Policy: 14.4 stays Windows only; D3D12 keeps being the default where its floor is acceptable and the D3D11 adapter would be selected by the host for the memory profile. (6) Risks: D3D11 flip-model swapchains with a waitable object and `Present1` damage rects are supported, DirectComposition and WARP work, device removal and recovery use the same DXGI events; GPU timestamps exist (`D3D11_QUERY_TIMESTAMP`); there is no equivalent of the pipeline cache blob (driver cache only), so the first-use shader creation cost has to be paid at startup.

## 12. Verification

- **Conformance suite:** the same `FramePlan`s run on every `GpuBackend`; output is diffed against `aqua-gpu-ref` with per-channel tolerances. Every tier of the D3D12 adapter runs it.
- **Differential fuzzing** of fast paths against reference implementations from one scene generator.
- **Replay determinism:** `Recorder<Runtime>` logs of `RuntimeInput` (the `Machine` input type, including ticks, frames, shell events, clipboard, IME and accessibility attach) replay into a fresh `Runtime` to identical outputs at every step and identical scene and lowered-plan hashes. Covered over `Runtime`, `RenderSide`, the transport lowering and the full `aqua` host composition (`aqua-verify/tests/host_full.rs`: `Aqua` + `UiApp` + `RenderLink` on the Reference, WARP, discrete and integrated adapters; identical settled frames across two replays, D3D12 within 1/255 of the Reference host).
- **Host replay:** `aqua-verify/tests/host_replay.rs` records a scripted wheel and click session on the live host (`Aqua` + `UiApp::record_session` + render thread, Reference and WARP backends) and replays the recorded `RuntimeInput` log three ways: into a fresh `Runtime` (identical `RuntimeOutput` at every step, identical scene hash), into a fresh `Runtime` plus `RenderSide` plus lowering plus backend (identical final frame hash to the live host's last presented frame), and through `Timeline` (seeking back and forward lands on the scene of the replayed prefix; a paused timeline freezes machine time). Two independent live sessions agree on the final scene and frame.
- **Exact counters:** allocations, instances, glyphs, layout nodes, passes per scene.
- **Text oracle:** DirectWrite pixel diffs (section 8).
- **Motion checks:** no one-frame jumps, no unmount above zero opacity, no motion on first mount, settle within declared bounds.

### 12.1 Reference semantics (`aqua-gpu-ref`)

`aqua-gpu-ref` defines what every `FramePlan` op means. Backends match it within the tolerances below. Pixel output is premultiplied linear-light RGBA, quantized to 8 bits per channel with round-to-nearest.

| Op | Reference definition |
|---|---|
| Frame start | The surface holds `plan.clear` (premultiplied). A plan that never writes the surface therefore yields the clear colour. |
| `LoadOp` | `Clear(c)` fills the whole target before the pass; `Load` and `DontCare` keep the contents, a never-written transient is transparent. |
| Quad | Signed-distance coverage `saturate(0.5 - d)` for the rounded rect, the same for the clip rect, border blended over the fill with `saturate(0.5 - inner)`, then `x opacity`. |
| Gradient | `t` is the projection of the pixel centre on `start -> end` (absolute pixel space), mapped through the two stop offsets and clamped. Colours interpolate in Cartesian Oklab (straight alpha), then premultiply. Backends may dither by at most half an 8-bit step. |
| Shadow | Exact Gaussian-blurred rounded rect: Gaussian-weighted integral over y of the closed-form erf x-extent of the rounded rect at that row. Spread grows the rect and the corner radius. `sigma < 0.05` is a hard signed-distance edge. |
| Glyph | Hard pixel-centre inclusion in `bounds`, nearest texel of the R8 atlas inside `texels`, multiplied by clip coverage and opacity. |
| Image | Quad coverage of `bounds` and `radius` times the coverage of `clip` rounded by `clip_radius` (ignored without a clip), bilinear sampling clamped to the `texels` sub-rectangle. Persistent RGBA8 data is premultiplied linear. `Blend::Over` composites `src * k` over the target; `Blend::Replace` yields `src * k + dst * (1 - k)` (premultiplied lerp), with `k = coverage * opacity`. Backdrop blur composites with `Replace`, so a translucent backdrop is replaced, not stacked. |
| `LayerOver` | `src * opacity` composited over the target. |
| Blur down / up | Dual Kawase. Down: 4x centre plus four diagonal taps at `0.5 * offset * (source/dest ratio, at least 1)`, divided by 8. Up: four axis taps at `offset`, four diagonal taps at `offset / 2` with weight 2, divided by 12. All taps are bilinear and clamped to the pass region. |
| Copy | Texel copy between `source_origin` and `dest_origin` of `size`. |
| ColorMatrix | Per pixel: unpremultiply (alpha 0 gives rgb 0), `out = clamp(M * [r g b a 1])` with the 4x5 row-major matrix applied to straight color, premultiply. Source and target extents must match. Implemented by the safe twin `aqua_kernels::color_matrix::reference`. |
| Custom | The reference runs a CPU kernel registered under `CustomPassSpec::name` (`Kernels::register_custom`); the standard set holds `aqua.invert`. A name with no kernel is `Unsupported`. Pass reads are inputs, the single write is the output; the HLSL contract is in section 14.9. |
| Compute | The reference runs a CPU kernel registered under the `ShaderId::Custom` id (`Kernels::register_compute`); the standard set holds id 1, a row box blur over 64-wide tiles (`groups = [ceil(w/64), h, 1]`, `params[0]` is the tap radius), so a partial dispatch leaves the rest of the target untouched. |
| Feature gating | A backend that reports `Features::color_matrix`, `compute` or `custom_passes` false is not asked to run plans that need them: the suite and the contract checks skip those cases (`conformance::requirements`) and report `SKIP: not offered by the backend`. Every other op is mandatory. |

### 12.2 Conformance suite

- `aqua_gpu_ref::conformance::run_suite(reference, backend, config)` runs hand-written cases (every op, clips, nested and sibling groups, degenerate geometry, odd extents) plus seeded fuzz scenes from one generator, then the backend contract checks (unknown surface, extent mismatch, invalid plan, determinism, surface reuse without residue, `recover`).
- The case list covers rounded clips (fractional, nested, under an outer clip, inside groups), bounded layers away from the origin and past the surface edge, backdrop replace on translucent surfaces, a blur-radius sweep across every octave boundary, color matrix, custom and compute passes, and explicit clear plans.
- Each pixel is classified `Interior`, `Soft` (shadow and blur footprints) or `Edge` (within `edge_band` pixels of any shape or clip boundary) and diffed per channel against the limit of its class. Defaults: interior 4, soft 8, edge 24 of 255 (measured on a Radeon RX 9070 XT and WARP: worst 1, 4 and 4).
- `tolerate_unsupported` turns `Unsupported` errors into reported skips. It was added for the wgpu adapter, which is deleted; no remaining backend uses it, and the D3D12 adapter must pass every case it is required to offer (`Features` gating, section 12.1).

Round 7 gate stability (verification area). Every change below cites the failure it removes.

- **Timestamp labels:** the per-pass timestamp labels (`scene/timestamps.rs`) already reuse preallocated vectors; `aqua-gpu-d3d12/tests/heap.rs` measured 0 allocations and 0 bytes per steady frame on all 56 combinations (WARP and the RX 9070 XT, Baseline and Bindless+enhanced barriers, 14 cases) three times in debug and twice in release. `d3d12_host_counters` and `heap_gates` also pass. The gates were not loosened.
- **`host_full` scroll glide (99 frames per notch on WARP):** the glide is time based, so the frame count is the glide duration divided by max(render interval, frame cost). The test attached the render link with a 2 ms interval, so a backend that rendered faster than the readback produced up to 99 frames and a slower one 20. The test now uses a 16.667 ms interval (one 60 Hz refresh); all four backends then present 19 frames per notch in release and debug. The step list now starts from the frame before the wheel, so the 77 px total is complete when the first glide frame already moved.
- **Refresh pacing (`warp_vsync`, `hardware_vsync`):** reproduced by starving the machine with 24 busy loops (4 of 6 runs failed with 1.5x to 6x the refresh interval). The measurement thread and WARP's worker threads were simply not scheduled. The tests now raise the process to the high priority class and the thread to time critical (`tests/support::prioritized`); the same stress then passes 5 of 5 on WARP and hardware (mean 6.04 to 6.11 ms against a 6.061 ms refresh).
- **`render_service` arrival, repaint, trim, share:** a viewport alone is a frame, so when the render thread picked up the viewport before the scene the tests saw one extra present (14 against 13, 5 against 4). Reproduced under 32 busy loops (13 test failures over 30 runs). The tests now wait for the viewport frame before scripting the scenario and count presents from that baseline; 40 of 40 runs pass under the same stress.
- **Memory budget:** the hardware run was once 99.6 MiB against the 96 MiB limit, entirely in the device and renderer stage (+75.7 MiB against +48.7 MiB in 13 other runs), right after other agents rebuilt the renderer. The offscreen backend compiles its pipelines without the on-disk pipeline library, so a driver shader cache miss compiles inside the process. The test now runs one priming child process first so the budget is measured against a warm driver cache. This is a hypothesis fitting the evidence (cold compile leaves about 27 MiB of driver memory), not a proof; a first launch on a machine that never ran the shaders is likely to pay it once.
- **Probe rows:** `heap_gates` now runs every runtime and render-side gate with a probe sink installed, adds `an_active_probe_sink_adds_no_allocations_to_idle_frames` (the sink must have seen spans and counts) and `the_profile_recorder_allocates_nothing_per_event_or_per_frame` (200 frames of every phase span nested, with counts, `begin` and `finish`). `tests/probe_heap.rs` compares steady `GpuFrames` presents on WARP without and with the sink: 72 heap events either way, so the probe adds 0. ### Closed decisions (formerly open)

**14.A Fence barriers.** Closed 2026-11-04 (round 4), off. Evidence re-checked this round: no `FenceBarrier`, `FENCE_BARRIER` or `BARRIER_TYPE_FENCE` symbol exists in `windows` 0.62.2 and none in `d3d12*.h` of Windows SDK 10.0.26100.0 (only `D3D12_BARRIER_TYPE_GLOBAL`, `TEXTURE` and `BUFFER`), so the API cannot be called from here. Earlier text: Preference: stay off until the bindings expose them. State: `hal::features` and `hal::tier` carry a `fence_barriers` flag that is always false; neither `windows` 0.62 nor the 10.0.26100 headers expose the API, nothing depends on the flag, and the tier is untested. Decision needed: none before the bindings ship; then enable behind the same tier flag and run `tests/tiers.rs` with it. Impact: only the synchronization cost between the render queue and upload copies, which the 0.12 ms p50 CPU submit does not show as a problem. Decision (2026-11-04, round 4, final): the question is closed until Microsoft ships the API. `windows` 0.62.2 (`D3D12_BARRIER_TYPE` has only `GLOBAL`, `TEXTURE` and `BUFFER`) and the 10.0.26100 headers contain no fence barrier type, no feature query and no command list method, so the tier cannot be implemented or exercised; `Tiers::fence_barriers` is false on every device and `Tiers::capped` can never turn it on. Queue-level fences stay the synchronization primitive between the render queue and uploads. Re-open when the bindings expose it: add the flag to `hal::features`, gate it in `tiers::resolve`, and add a fifth combination to `tests/tiers.rs` and `tests/debug_layer.rs`. Earlier decision (round 3): fence barriers stay off. The adapter has no code path for them, `Tiers::fence_barriers` is false on every device, and no test or budget depends on them; the enhanced-barrier tier already removes the per-pass legacy transition cost that they would otherwise help with.

**14.B DirectComposition path.** State: `aqua-shell-win32::composition` exists (Mica and backdrop materials); the D3D12 `WindowBackend` presents through `CreateSwapChainForHwnd` and has no composition swapchain. Consequences today: `WindowError::Unsupported` for transparent windows and materials (record 14.15), and Mica pixels are unverified. Closed 2026-11-04 (round 4). Decision: a composition swapchain (`create_composition_surface`, premultiplied alpha, attached with `Window::attach_composition_surface`) only for windows that need an alpha surface (`material::needs_alpha_surface`: Mica, Mica Alt, Acrylic or a transparent window); every other window keeps the hwnd swapchain, so the common path pays no composition cost. Evidence (re-run): `window/composition.rs` 6 of 6 on the RX 9070 XT and WARP (Mica, Mica Alt and Acrylic show the backdrop through alpha 0, opaque quads exact, survival of resize and device loss), measured through `PrintWindow`. Not measured: the memory delta of a composition chain against the hwnd chain, and `Present1` dirty rects on a composition chain; neither changes the decision because composition is opt-in. The host now does this (round 4, record 14.N): `native/d3d12.rs` creates the composition surface for a window whose clear colour is transparent (which `Config::resolve` forces for every material), hands its content to the UI thread through `CompositionSink` and `NativeWindow::attach_composition`, and hands it over again after a recovery. Verified on Windows that the surface attaches and re-attaches after an injected device loss (`tests/render_shared.rs`); Mica, Mica Alt and Acrylic pixels on the host window are checked in round 5 (`tests/host_material.rs`, 14.N).

**14.C Pipeline cache persistence.** Preference: persist. State: `PipelineSet` builds and serializes an `ID3D12PipelineLibrary` (`scene/pipeline.rs`, `SceneRenderer::serialize`) and accepts bytes at construction, ignoring corrupt or foreign data; at the time of writing the host passed `None` and never wrote the bytes. Closed 2026-11-04 (round 4): persist, and it is implemented. The host (`render/persist.rs`, `native/d3d12.rs`) reads `pipelines.cache` from the user cache directory before device creation, passes it to `WindowBackend::with_pipeline_cache`, and writes it back when its fingerprint changed; a corrupt or foreign library is ignored and the pipelines compile (`tests/pipeline_cache.rs`: warm start compiles 0 and loads every cold-compiled pipeline on WARP and the RX 9070 XT; a corrupt library compiles). One file rather than one per adapter, because `ID3D12PipelineLibrary` rejects data from another adapter or driver itself. Cold versus warm timing, measured by running the test executables natively: the whole `hardware_reloads` test (two device creations, a cold build, a warm load) takes 0.31 to 0.36 s on the RX 9070 XT, the `warp_reloads` test 0.09 s, and the cold-only corrupt-library test on WARP 0.07 to 0.09 s, so the warm start saves less than the test noise (about 20 ms) here. The pipelines come from prebuilt DXIL, which is why. The cache stays because it is already written and costs one small file, but it is not what decides time to first frame.

**14.D Shared device.** State at the time of writing: one render thread and backend per window in the host, so a second window pays the 43 MiB device floor again. Closed 2026-11-04 (round 4): the device is shared at the backend. One `WindowBackend` owns one `Core`, queue, renderer and texture set for any number of windows (record 14.8), and `window/shared_device.rs` passes 4 of 4 on the RX 9070 XT and WARP (two windows of different size, resize and close of one leaving the other untouched, loss and recovery rebuilding every window). ### Decision records

### 14.P Mesh viewport (decided 2026-11-04, `aqua::render::mesh`, `aqua::ExternalFrame`)
Meshes stay a CPU-rasterized image path: the host rasterizes `DisplayItem::GpuiMesh` (up to 400,000 triangles) at the item's pixel size, caches it per mesh id and style, and lowers it as an image item. A GPU mesh pass is not added: the port's viewport is a preview, the oracle has no depth-tested triangle pass to conform against, and the D3D12 plan stays a 2D display list. `ExternalFrame::meshes_supported()` returns true so applications enable the viewport; reopen if a workload needs interactive frame rates on large meshes. `aqua` no longer depends on `accesskit` directly; its accessibility test uses the re-export from `aqua-a11y-uia`.

### 14.1 Text look (decided 2026-11-04)

one consistent rasterizer on every platform: unhinted skrifa outlines, grayscale coverage at 4 horizontal subpixel positions with y snapped, no LCD subpixel rendering. The Windows native look is reproduced at blend time by the Microsoft gamma and contrast model keyed on text luminance (`aqua_text::tone::ToneCurve::native`, gamma 1.8, grayscale contrast 1.0). Evidence (section 8.1): unhinted coverage agrees with DirectWrite to a few percent, shaping agrees exactly, and the tone curve brings blended ink within about 6% of DirectWrite's own grayscale output, where the plain coverage was off by 13 to 22%. DirectWrite grid fitting is deliberately not matched (it moves stems vertically by up to a pixel at 13 px); ClearType color fringing is not offered. DirectWrite stays test-only.

### 14.2 UIA: decided, AccessKit's Windows adapter

(`accesskit_windows` 0.35 `SubclassingAdapter`, no winit). Evidence, 2026-11-04: the runtime already emits an AccessKit-shaped snapshot (roles, bounds, text runs, selection) and `aqua-a11y-uia` feeds it through unchanged; a real UIA client (`IUIAutomation`, `FindAll` over the descendants, the Invoke pattern) round-trips against it on Windows in `crates/aqua-a11y-uia/tests/uia_windows.rs`: control types, names, bounding rectangles, Invoke arriving as `A11yAction::Press`, and live relabeling after an update. Hand-written UIA would have to reimplement the element, fragment, fragment-root, text, value, toggle, expand-collapse, range-value, selection and grid providers plus the event queue, with no behavior the adapter lacks. The adapter costs nothing until a client connects: attaching installs one window subclass, `request_initial_tree` only flips the bridge to connected and wakes the host, and no tree is built while dormant. Two constraints follow from it: attach before the window is first shown (`UiaAdapter::attach` returns `WindowAlreadyVisible` instead of panicking), and a `Role::Label` node gets its name from `value`, so the snapshot copies the label into the value for text nodes.

### 14.3 Render thread ownership

decided 2026-11-04: a pure state machine driven by the host. `aqua_runtime::RenderSide::step(RenderInput) -> RenderOutput` owns the presented scene and a `aqua_motion::TrackSet`, reads no clock and spawns no thread. The host (`aqua-transport::spawn_render_thread` with a `RenderHost` supplying the clock, the frame wait and GPU execution) owns the thread and moves `RenderCommand`/`RenderEvent` over a safe SPSC ring. App side: `aqua_motion::AppMotion` (targets, policy, owners, completions; never samples) plus `aqua_runtime::emit_scene_diff` (drains the app `Scene` into a `SceneDiff`). Completion callbacks fire on the app side when a `Settled { track, generation }` event with the current generation arrives. Motion times are `f64` seconds on the host clock (`Instant::as_secs_f64`); presentation time arrives as `RenderInput::present_at`. Round 2 (2026-11-04): `aqua_transport::GpuRenderHost<B, L, C>` is the `RenderHost` over any `GpuBackend<Error = GpuError>` (the D3D12 `WindowBackend`, `OffscreenBackend`, `RefBackend`). It lowers the render-side scene to `PaintCommand`s through a `Lowering` (`GeometryLowering`: quads, shadows, clips, opacity, content and backdrop blur, translation transforms; text, images and vectors are counted as `unsupported_items` until a richer lowering is plugged in), plans with the backend's `plan_limits`, waits for the frame slot once per frame (`wait_for_frame_slot`, the swapchain's waitable object on D3D12), executes and presents. `spawn_render_thread_with` builds the host on the render thread, because COM-backed backends are not `Send`; the loop now waits on the frame slot before sampling tracks, so `present_at` is the clock plus one frame interval measured after the wait, and `RenderWake::At` blocks on the command ring instead of spinning. A device failure is reported as `Feedback::DeviceLost`; the next frame calls `recover`, recreates the surface and reports `DeviceRecovered`, which makes `RenderSide` resubmit. `RenderSide` now submits a frame when the viewport changes as well as when the scene revision does. The inspector (`aqua_transport::InspectorServer`) is a loopback-only TCP socket speaking one JSON line per request: `stats` (frames presented and failed, device losses, scene items, tracks, last frame record with passes, instances, barriers, CPU and GPU time, present queue time, unsupported items), `tree` (the accessibility-tree JSON the host publishes) and `watch` (a line per published change); it refuses non-loopback addresses. Popups and scroll glide are routed through tracks. `OverlayHost` owns the single app-side `AppMotion` (`tracks_mut`); `animate_popup(overlay, PopupMotion { property, from, to, kind }, now)` registers an opacity or translate animation, the runtime wraps that popup's portal subtree in a `PushOpacity`/`PushTransform` group (`SceneKey::PortalStart`/`PortalEnd`), binds a track to the group's scene node once it exists and emits `Spawn` and `SetTarget` after the scene diff; closing the popup removes the track. Every scroll node's content is wrapped in an identity `PushTransform` inside its clip (`SceneKey::ScrollContentStart`/`ScrollContentEnd`). A wheel notch moves the logical scroll offset to its final, clamped value at once (layout, virtualization and hit-testing see the target state) and queues the applied distance; the runtime then emits `MotionCommand::Shift`, which moves the presented translation by that distance and retargets to zero with the carried velocity, so the render side glides the content with a critically damped spring (`glide::kind`, 0.25 s) and the app side does no work while it glides. `Track::retarget` and `Track::shift` now advance the track to the retarget time before launching the new segment, which removes a position error of up to one frame of travel when a retarget lands between samples. `MotionController` remains for author-driven values that need app-side sampling. Remaining: damage-limited presentation from the scene footprints, and moving author-driven `MotionController` values onto `AppMotion`.

### 14.5 `aqua-kernels` scope (decided 2026-11-04)

the crate has no dependencies, denies `unsafe_op_in_unsafe_fn`, and every module that uses `unsafe` exports a safe `reference` twin plus a dispatching `apply`. Kernels: `color_matrix` (4x5 matrix over premultiplied f32 pixels, SSE2 on x86_64), `over` (premultiplied span composite with opacity, SSE2) and `diff` (max absolute byte difference for conformance compares and damage detection, SSE2). The fast paths are bit-identical to their twins (same operation order, no fused multiply-add), proven by differential tests in `crates/aqua-kernels/tests`, and other architectures fall back to the twin. The oracle (`aqua-gpu-ref`) calls only twins. `aqua-verify/tests/kernels.rs` enforces: no dependencies, the deny attribute, a twin and a differential test for every unsafe module, and twin-only use by the oracle. Hot paths are admitted when a measurement shows the twin costing frame time; none beyond these three is justified yet. **Profile evidence (2026-11-04, `aqua-verify/tests/profile.rs`, release, Windows x86_64):** the three SSE2 kernels do not earn their `unsafe` on the target: `over` over 3.69 million RGBA32F pixels takes 3.06 ms in the safe twin and 3.02 ms in the SSE2 path (Linux: 4.6 versus 3.3 ms), and `diff` over 14.7 MB takes 0.24 ms versus 0.28 ms (the twin auto-vectorizes). Runtime hot paths measured are all in safe code and mostly in external crates: 1900 glyph rasterizations (skrifa, 5 sizes x 95 glyphs x 4 subpixel offsets) cost 10.9 ms including a 4 ms first-face load (5.7 microseconds per glyph), and 2000 wrapped paragraphs shape cold in 37 ms and re-wrap in 18 ms. The only hot path found is the oracle's shadow integration: at 2560x1440, 7 shadows of sigma 16 take 50.7 s of CPU while 148 quads take 51 ms, 4001 glyphs 75 ms and a backdrop blur 60 ms, so shadows are 99.6% of an oracle frame (a numeric y-integral of two f64 `erf` calls per step, about 48 steps per pixel). Decision: no kernel is admitted for the runtime; the rule stays as written (a kernel needs a measured speedup of at least 1.5x over its twin on the Windows target), `color_matrix`, `over` and `diff` stay only because they exist and are twin-tested, and the first fix for the oracle's cost is algorithmic and safe (hoist the per-row sample weights and half-widths out of the per-pixel loop, bound the footprint), with a batched `erf`-sum kernel admitted only if that is still above 1 s per 1440p shadow frame.

### 14.6 D3D12 device core decisions (2026-11-04, `aqua-gpu-d3d12::hal`)

the Bindless tier requires Shader Model 6.6 and Resource Binding Tier 3; enhanced barriers follow `D3D12_OPTIONS12`; fence barriers and batched copy lists stay off (decision 14.A). A device that fails the baseline (feature level 11_0, SM 6.0) is skipped and the chain ends at WARP. After a device loss the same adapter is re-selected by LUID; a second loss within 10 s falls back to WARP. Recovery consumes the old core so the removed device is released before the replacement is created, which WARP requires. The first `Present` on the RX 9070 XT adds about 40 MB of driver-private commit (WARP: 0.1 MB), so the section 11 budget has to be measured with the real driver in place.

### 14.7 D3D12 scene pipelines and shaders (2026-11-04, `aqua-shaders`, `aqua-gpu-d3d12::scene`)

HLSL under `crates/aqua-shaders/hlsl` is compiled by `build.rs` to signed DXIL, Shader Model 6.0, with `dxc` found through `AQUA_DXC`, `PATH` or the Windows SDK (`dxc.exe` runs from WSL through `wslpath`); the build fails without it, and the adapter never compiles shaders at run time. The plan carries barriers, load ops and aliasing; the executor translates them against a per-resource tracked state (the plan's `from` and `Undefined` are ignored, so an aliased transient is moved from wherever it last was), emits an aliasing barrier at every transient's first use in a frame, and re-places the planner's heap offsets with real allocation sizes (`placement::place`) because D3D12 tile padding makes RGBA16F textures larger than `texels * 8`. Offscreen surfaces default to RGBA16F; BGRA8 UNORM and sRGB targets are supported by passing the render-target view format in `SceneTarget`, and a `Copy` pass whose source and destination formats differ (backdrop snapshots from an 8-bit window surface) is executed as a draw instead of `CopyTextureRegion`. Pipelines are keyed by (kind, target format), prebuilt through `warm`, and loaded from a serialized `ID3D12PipelineLibrary` passed in as bytes (a corrupt or foreign library is ignored); `SceneRenderer::serialize` produces the bytes, but the host stored and supplied by the host since round 3 (decision 14.C). At the time of writing the adapter did not cover `ColorMatrix`, `Custom` and `Compute`, the Bindless and enhanced-barrier tiers, or rounded clips and `Replace` blending; all are built since (records 14.12, 14.13, 14.16).

### 14.8 D3D12 window backend (2026-11-04, `aqua-gpu-d3d12::window`)

`WindowBackend` owns a `hal::Core`, one `Swapchain` per `SurfaceTarget::Native`, one `SceneRenderer` and one `PersistentTextures`, and implements `GpuBackend` plus `GpuReadback` (reads the unpresented back buffer). Frame order: `wait_for_frame_slot` (the waitable), `execute` (`Core::begin_frame`, upload batches, scene record, `end_frame` signals the timeline), `present` or `present_with_damage`. Swapchains are `FLIP_SEQUENTIAL`, not `FLIP_DISCARD`: DXGI returns `DXGI_ERROR_INVALID_CALL` from `Present1` for any non-empty dirty rect on a `FLIP_DISCARD` chain (measured on the RX 9070 XT and WARP), and sequential flip keeps the buffer contents the age tracking relies on. Damage: `window::damage::DamageTracker` keeps the last-presented frame per buffer and a short history; `repaint_region` returns what a buffer needs repainted (its age worth of damage plus this frame's), `Damage::Full` for unknown buffers, after resize, after an occluded present or when history ran out. An empty damage slice means full. The executor still redraws the whole surface every frame, so today the tracker feeds only `Present1` dirty rects (this frame's damage) and the `repaint_region` query; scissoring the plan to the repaint region was added in round 3 (below). Recovery (`recover`): wait idle, drop swapchains, renderer and textures, `Core::recover` (or a fresh WARP core if an earlier recovery failed halfway), rebuild renderer (reusing the serialized pipeline library when the old device still serializes it), recreate every swapchain on its HWND, drop pending uploads, then call the recovery listener (`RecoveryNotice { generation, software }`); the host must call `Residency::clear` there because persistent textures are not mirrored. Failed calls probe `Core::check_removed` and latch `device_status() == Lost`; the host reacts by calling `recover`. `FrameReport::gpu_time` is filled from `SceneRenderer::gpu_time()` (`window/backend.rs`). Scissored repaint and composition surfaces were added in round 3 (below).

Round 3 (2026-11-04): (1) Scissored repaint: `WindowBackend::execute_damaged(plan, inputs, damage)` computes `repaint_region` for the current back buffer, collapses it to its bounding rectangle (D3D12 has one scissor per viewport), and `SceneRenderer::record_region` confines every pass that writes the surface, clears included, to it; layer transients stay unscissored. The frame's own damage is remembered, and `present` commits it and sends it as `Present1` dirty rects. Unknown buffers, resize, occlusion and exhausted history repaint in full, and the first present after any reset is sent without dirty rects (DXGI returns `INVALID_CALL` for dirty rects on a first present). On the RX 9070 XT and WARP, pixels outside the region keep the previous frame, pixels inside match `aqua-gpu-ref`, and every scissored frame matches the oracle. (2) The swapchain render target view is `B8G8R8A8_UNORM_SRGB` over the `B8G8R8A8_UNORM` buffer (`hal::RENDER_FORMAT`). Before this the window path wrote linear values into a UNORM view and showed dark colors (`#3b82f6` came out as 11,57,235). Readback converts back to linear for the oracle compare. (3) DirectComposition: `create_composition_surface` makes a `CreateSwapChainForComposition` chain with `DXGI_ALPHA_MODE_PREMULTIPLIED`, and `composition_content` returns the `IUnknown` for `Window::attach_composition_surface`. `recover` rebuilds composition surfaces, and the host must attach `composition_content` again after a recovery notice. Pixel-checked through `PrintWindow` on an `alpha_surface` window: Mica, Mica Alt (`Tabbed`) and Acrylic show the backdrop through alpha 0 pixels (32,32,32, 32,32,32 and 84,84,84), opaque quads are exact, and an opaque clear hides the material. Known limit: the sRGB view encodes premultiplied linear color, so a translucent pixel over the material composes as `enc(c*a) + (1-a)*backdrop` instead of the gamma-space `a*enc(c) + (1-a)*backdrop`. Fully opaque and fully transparent pixels are exact. A final un-premultiply, encode and premultiply pass for composition surfaces would fix it and is not built. (4) Shared device: one `WindowBackend` owns one `Core`, one queue, one renderer and one texture set for any number of windows, tested with two windows of different size, resize and close of one, and loss and recovery of both. The backend is not `Send`, so the host must drive all windows from one render thread to share it. (5) Refresh pacing: `window::timing` reads the DWM composition period, `EnumDisplaySettings` gives the window monitor's rate, and `pacing::reconcile_interval` trusts the DWM period only when it agrees with the monitor within 1%. On this machine the test window sits on a 165 Hz monitor while the DWM composition clock is 240 Hz (4.167 ms). Vsync presents average 6.06 ms (the monitor interval) but land on 4.17 ms composition ticks, so frame gaps alternate between about 4.2 and 8.4 ms, which the swapchain cannot change. `WindowBackend::pacing` reports frames, missed vblanks, mean and worst. (6) Texture recovery: persistent textures are not mirrored by default. The host calls `Residency::clear` and re-uploads (`RecoveryNotice::textures == HostMustReupload`), and a draw of a texture that was not re-uploaded fails. `WindowOptions::mirror_textures` (env `AQUA_MIRROR_TEXTURES=1`) keeps a CPU copy of every persistent texture and replays it on the new device (`Replayed { textures }`). It doubles atlas memory, so it is off. (7) Adapters: the integrated `AMD Radeon(TM) Graphics` (485 MiB) and the RX 9070 XT both open and present to a window on the 9070 XT's monitor (the integrated one across adapters), matching the oracle within 2/255. A failed record now closes the command list and keeps queued uploads.


### 14.9 Runtime as a `Machine` (decided 2026-11-04, `aqua-runtime::Runtime`)

`Runtime` implements `aqua_protocol::Machine` over `RuntimeInput`/`RuntimeOutput`; the protocol types are `aqua_protocol::Input`/`Output`, re-exported as `RuntimeInput`/`RuntimeOutput`. A step is infallible: build errors go to `build_error()` and `take_diagnostics()`. The runtime binds the first window id it sees and addresses every `ShellCommand` to it; `open_window`, `submit` and `request_dialog` queue commands that the next step emits. Per step it emits: `RequestFrame` for input, resize, due wakes and recovery; `SetCursor` and `SetDragRegions` on change; `Viewport` then `Scene(SceneDiff)` after a frame (first frame is the full scene plus order, idle frames emit nothing); IME `Enable`, `Update` and `Disable` from the focused editor's revision, selection, composition and caret area (document windowed by `aqua_ui::events::ime_surroundings`); `ime_area` on change; and `access` as a full `AccessTreeUpdate`, only while an assistive client is attached (`Input::AccessClient { connected }`, an input so replay logs stay complete) and only when the tree epoch, focus or scale changed. Clipboard shortcuts become `ClipboardWrite` and `ClipboardRead { request }`, and the `ShellEvent::Clipboard` answer pastes text; image and file clipboard payloads are not carried by the shell protocol yet. File drag and drop follows `FileDropEvent` with the last pointer position. A `Tick` at or after the last `wake_at` requests an `ANIMATION` frame. `Recorder` plus `replay` and `first_divergence` reproduce every output byte for byte (`crates/aqua-runtime/tests/runtime.rs`).

### 14.10 Bounded layers and per-pass origin (2026-11-04, `aqua-graph::paint`)

a layer's transient is sized to the pixel-aligned union of its children clipped to the clip and target (a 1440p group of 200x40 px costs 64 KB instead of 29 MB). The origin lives in the planner, not in the pass: children are emitted in layer-local coordinates (bounds, clips, gradient endpoints and shadow footprints are translated by the layer origin), so passes, backends and the reference need no origin field and stay source compatible. The composite is an `Images` instance whose `bounds` sit at the layer origin in the parent's coordinates and whose `texels` are the whole layer, which samples exactly at texel centers. Rounded clips use the same mechanism with `clip` set to the exact fractional rect and `clip_radius` to the corner radius, so the rounded edge is analytic and independent of pixel alignment.

### 14.11 Custom pass contract and blur continuity (2026-11-04)

a `Custom` pass is a full-target pixel shader. HLSL entry signature: `float4 entry(CustomInput input) : SV_Target` with `struct CustomInput { float4 position : SV_Position; float2 uv : TEXCOORD0; }`, inputs `Texture2D<float4> input0..input7` at `t0..t7` in `reads` order, parameters `cbuffer Parameters : register(b0) { float4 parameters[N]; }` packed from `CustomPassSpec::params`, one `Load` per pixel addressed by `position.xy`; `bounds` is in the output's pixel space. The adapter compiles and caches it by `name`; until it does, it reports `custom_passes` false. Blur is continuous in the radius: below 2 the pyramid is one level with `offset = radius / 2`; above, the lower depth `floor(log2 radius)` is used alone until 75% of the octave, then crossfaded into the next depth (`BlurDepth::Mixed`, two pyramids lerped by two `Replace` image instances) so that at `radius = 2^k` the output equals the single pyramid of depth `k` with offset 1 from both sides. The crossfade costs a second pyramid only in the top quarter of each octave.

### 14.13 D3D12 tiers, transients and timing (2026-11-04, `aqua-gpu-d3d12::scene`, `aqua-shaders`)

`SceneOptions { limit: TierLimit, transient_ceiling, timestamps }` selects tiers; the default is the best tier the device offers (`hal::detect` then `scene::tiers::resolve`). **Bindless:** every pixel shader is also compiled as `<entry>_bl` (Shader Model 6.6, `-D BINDLESS`) with the texture read through `ResourceDescriptorHeap[texture_index]`; the index travels in root constant dword 14 and the root signature is the 16 constants plus the static sampler with `CBV_SRV_UAV_HEAP_DIRECTLY_INDEXED`, so passes and image runs set one constant instead of a descriptor table. `SetDescriptorHeaps` must run before `SetGraphicsRootSignature` for such a signature (the RX 9070 XT returns garbage otherwise, WARP does not care). **Enhanced barriers:** transients are created with `CreatePlacedResource2` and an initial layout; surface and transient transitions become texture barriers derived from the tracked legacy state (`barriers::access_of`), a transient's first use is an activation barrier (`LayoutBefore` undefined, discard) instead of an aliasing barrier, and persistent atlas pages keep legacy barriers because the upload path owns their state. **Fence barriers: not implemented.** Neither `windows` 0.62 nor the 10.0.26100 SDK headers expose them, so the tier is reported off and nothing in the adapter depends on it; revisit when the bindings ship. **Transient heap:** `policy::HeapGate` sizes the heap to the plan's re-placed total plus 25% growth slack, keeps it while the plan needs more than half of it, shrinks it after 240 frames below half, and rejects a plan above `transient_ceiling` with `Error::Budget` instead of allocating; `SceneRenderer::trim(&Trim, fence)` releases the heap behind the frame fence and shrinks upload and descriptor slots back to their initial size (`hal::budget::trim_for` decides when). **Timestamps:** two `EndQuery` stamps bracket `SceneRenderer::record` per slot, resolved into a readback buffer and read in `retire` once the slot fence passed; `gpu_time()` is the latest finished frame (one to three frames old), taken from a throwaway direct queue's `GetTimestampFrequency`. The window backend must copy `renderer.gpu_time()` into `FrameReport`. Verified with `tests/tiers.rs` (every tier combination against the Baseline tier's results on WARP, the RX 9070 XT and the minimum-power adapter, plus BGRA8 on the top tier), `tests/transients.rs` and `tests/heap.rs` (exact allocation counts per steady frame: 23, 11 and 14 for the group, glyph and image cases).

### 14.16 Effects, validation and the zero-allocation gate (2026-11-04, `aqua-gpu-d3d12::scene`, `aqua-shaders`)

**ColorMatrix:** `ps_color_matrix` (`color_matrix.hlsl`, also built as `_bl`) unpremultiplies, applies the 4x5 row-major matrix to straight color, saturates each channel and premultiplies, matching `aqua_kernels::color_matrix::reference`. The root signature grew from 16 to 36 root dwords: dwords 0 to 15 are the frame constants, dwords 16 to 35 the matrix (`matrix_rows[5]` in `common.hlsli`), written by `Binding::set_matrix` only for that pass. **Custom:** the pixel shader is compiled at run time with `D3DCompile` as Shader Model 5.1 (`ps_5_1`; the `windows` bindings expose no DXC), cached by a hash of name, entry and source plus the target format, with a run-time compiled `vs_5_1` fullscreen vertex shader so no DXIL and DXBC stages are mixed. It uses its own root signature: a root CBV at `b0` fed from the slot upload buffer (parameters padded to a 256 byte block) and a table of eight SRVs at `t0..t7`, padded with null descriptors; the scissor is `bounds`, and a compile error is returned as `Error::Shader` (the half-recorded command list is closed, so the backend keeps working). **Compute:** `ShaderId::Custom(id)` selects a registered shader; id 1, the row box blur of the reference, is a build-time DXIL `cs_row_box_blur`, others come from `register_compute` (`cs_5_1`, entry chosen by the caller). The pass has a root signature of four constants at `b0`, eight SRVs and one UAV; its output must be a transient, which is then created with `ALLOW_UNORDERED_ACCESS` (only transients written by a compute pass pay for it). Reads of transients and the surface now use `PIXEL | NON_PIXEL_SHADER_RESOURCE` (persistent atlas pages keep the pixel-only state), and a second compute write to a texture already in the UAV state gets a UAV barrier. **Verified on Windows:** all 6 conformance variants (float, BGRA8, sRGB on WARP and the RX 9070 XT) pass, including `color_matrix_*` (max difference 1), `custom_invert_*` (1) and `compute_row_box_blur` (1); `tests/effects.rs` covers packed parameters, compile errors and `register_compute`.

**Debug layer:** `AQUA_D3D12_DEBUG=1` enables the layer (and `AQUA_D3D12_GBV=1` GPU-based validation) in `scene::device::select`; `OffscreenBackend::debug_errors` drains the info queue. `tests/debug_layer.rs` renders every conformance case twice on all four tier combinations (Baseline, Bindless, enhanced barriers, both) on WARP and the RX 9070 XT (float and BGRA8) with GPU-based validation and asserts zero error or corruption messages. It found and fixed two legacy-barrier errors: a placed render target must be initialized with `DiscardResource` after its aliasing barrier, and the discard needs the resource in `RENDER_TARGET`, so activation now emits the aliasing barrier, a transition to `RENDER_TARGET` from the tracked state and the discard before any other barrier of the pass (`Batch::pre`). The enhanced-barrier and bindless paths were clean.

**Zero allocations:** a steady frame (same plan as the previous one) performs no heap allocation in `GpuBackend::execute` on the offscreen backend: packing goes straight into a reused byte buffer (`Scratch`), the tracked-state map, the activated set and the per-pass read bounds are reused, image runs are an iterator, barrier batches are pooled in `Emitter`, and `Validated` skips `validate` when the plan equals the one it last accepted (a changed plan validates and clones with `clone_from`). `tests/heap.rs` gates 11 cases, covering group, glyph, image, blur, rounded clip, color matrix, custom and compute, at exactly 0 allocations and 0 bytes on both tier extremes of WARP and the RX 9070 XT; `AQUA_HEAP_TRACE=1` prints the allocating call sites. Frames whose plan changes still allocate (validation and the plan clone).

### 14.U Round 6 closure: shadow hard edge, repaint feedback, wake from signals, port lint set (decided 2026-11-04)

- **Shadow hard-edge threshold.** A shadow whose Gaussian sigma is below 0.05 logical pixels is a hard signed-distance edge, in both the oracle (`aqua-gpu-ref::shadow::HARD_EDGE_SIGMA`) and the D3D12 shader (`shadow.hlsl`, `HARD_EDGE_SIGMA`); at or above it the Gaussian-weighted integral of section 12.1 applies. ### 14.14 Text blending on a linear pipeline (decided 2026-11-04, `aqua-graph::tone`, `aqua-shaders/hlsl/glyph.hlsl`, `aqua-text::residency`)

the glyph pass applies `ToneCurve::native().linear_blend_alpha(coverage, luminance)` to every mask sample, where `luminance` is the sRGB-encoded luminance of the instance color (unpremultiplied first) and the curve parameters travel in the pass constants (`region` = the four ratios, `values.x` = contrast), so the curve is a data input and not recompiled. Mask instances from vector paths pass through the same function. The remap assumes the backdrop is the opposite extreme of the text; against a mid-tone backdrop the result is between the plain linear blend and DirectWrite's (gray 200 on 30 measures 0.88 to 0.96 of DirectWrite's ink). Alternative rejected: blending glyphs in encoded space, which needs a backdrop read per glyph. One glyph identity everywhere: `GlyphKey.font` is an interned face index owned by the `GlyphResolver`, sizes are quantized to 1/64 px before they enter any key, and `aqua-text` keeps no atlas.

### 14.O Slug curves, backdrop-aware glyph blending and instance transforms (decided 2026-11-04, round 4; `aqua-graph::slug`, `aqua-graph::linear`, `aqua-text::slug`, `aqua-shaders`, `aqua-gpu-ref::sprites`, `aqua-gpu-d3d12`, `aqua::render::lower`)

Decisions, each with the alternative that was rejected:

- **One float store, not two buffers.** Curves, band headers, band ranges and curve-index lists share one persistent `Rgba32Float` texture of fixed width 1024 texels (`TextureHandle(u32::MAX - 1)` for the host, `TextureHandle(3)` in the conformance assets), addressed linearly (`index % 1024`, `index / 1024`) and read with `Load`. A glyph is a record: 4 header texels (em bounds; horizontal origin, bands per em and the two band counts; vertical origin, bands per em and the two range-table offsets; the index-list offset), the horizontal then vertical range texels (`offset, count`), 2 texels per quadratic curve (`p1.xy p2.xy`, `p3.xy`) and the curve-index lists packed four to a texel. The two band sets are ordered by descending far edge so a scan stops at the first curve behind the sample, exactly as in the CPU reference. Rejected: separate curve and band textures (a second SRV per pass changes the root signature and the bindless constants for every pass) and `Rgba16Float` curves (11 bits of mantissa give 0.1 px error at 200 px). The layout, the instance type, the pure evaluator (`slug::coverage`) and the outline-to-record packer (`pack_glyph`, with `SlugGlyph`, `PathCommand`, the cubic-to-quadratic split and the band builder) live in `aqua-graph::slug`, so the oracle and the conformance assets need no font stack; `aqua-text` re-exports them and adds `SlugCache` (outlines from skrifa) and `SlugStore` (the arena: append-only, grows by recreating the texture at a power-of-two row count, emits `Release`/`Create`/row `Write` uploads, `reset` after a font-set change, device loss or a full trim). A device that loses textures needs no extra step: `reset` makes the next `uploads` recreate the store.
- **`PassKind::Slug { store, instances }`.** `SlugInstance` carries the screen origin of the em origin, a 2x2 em-to-screen matrix (pixels per em and the y flip folded in with the placement), the glyph record index, the em bounds, color, clip, opacity and optional backdrop. The pass reads exactly the store texture. The planner culls, merges (same store) and sizes layers by the instance's covered rectangle. The shader (`slug.hlsl`) maps the pixel centre back to em space with the inverse matrix, uses the matrix determinant's square root as pixels per em, and runs the same two band scans as the oracle; the quad covers the transformed em bounds plus one pixel. Pixels per em is isotropic, so a strong anisotropic scale blurs one axis slightly.
- **Backdrop luminance is instance data.** `GlyphInstance` and `SlugInstance` have `backdrop: Option<f32>` (sRGB-encoded luminance, packed as a negative number for `None`). `Some(b)` selects `ToneCurve::linear_blend_alpha_over(coverage, luminance, b)`, `None` keeps the contrasting-backdrop assumption of 14.14; HLSL and the oracle use the same expression. Rejected: reading the render target per glyph (needs a copy of the target before every glyph pass and breaks batching). The host fills it in `render::lower`: it remembers the last 256 nearly opaque (alpha 0.98 or more) solid fills with their luminance, and a text run takes the most recent of the last 64 whose rectangle contains the run's first line midpoint, else the opaque clear colour, else `None`. Translucent fills, gradients and images never count, so text over them keeps the old assumption.
- **Instance-level rotation and skew.** `QuadInstance` and `ImageInstance` have `linear: Linear2` (identity by default), a 2x2 matrix applied about the centre of `bounds`; `bounds` stays the unrotated rectangle, so radii, border widths and gradients are in local units and the matrix scales them. The vertex stage covers the bounding box of the transformed rectangle plus one pixel (`QuadInstance::covered`, used by the planner, the culler and the conformance footprints). The pixel stage computes the local position `centre + inverse * (p - centre)`, takes distances there and multiplies them by the square root of |det| for anti-aliasing; clips stay in screen space, and an identity matrix takes the old code path bit for bit. `PaintCommand::Linear { linear, leaf }` wraps a `Quad`, `GradientQuad` or `Image` (anything else is `PlanError::NotTransformable`); `PaintCommand::Slug(SlugRun)` carries slug glyphs. Sprite vertex data grew from 4 to 5 vec4s (`SpriteGpu.extra` is the backdrop for glyphs and the matrix for images) and quads from 9 to 10 (`XFORM`). Shadows, clips and blurs do not rotate: the host maps them to the bounding box.
- **Host lowering.** An item drawn under a transform that is not a translation, uniform or non-uniform scale (`!Affine::is_exact`) is emitted in device space as before and then lifted: quads, gradient quads and images become `Linear` leaves with their centre moved through the transform; non-uniform corner radii and uneven or dashed borders (clip-based decompositions that cannot be rotated) are flattened to the largest radius and width and counted as approximated; shadows, clips, content blur and backdrop blur take the bounding box and are counted. `PushTransform` itself is no longer reported as approximated. Text is placed with the full matrix and uses Slug when the run sits under a transform that changes the scale or rotates or skews (`moving`), or when a glyph is at least 160 px; glyphs the store cannot hold (color glyphs, fake bold) fall back to the atlas path. `LowerReport.curves` counts slug glyphs.

Verified on Windows (RX 9070 XT and WARP): the conformance suite has 133 cases (11 new: slug at three sizes, rotated and skewed slug, slug clipped in a group with opacity, slug and atlas glyphs over a mid-tone with a known backdrop, rotated and skewed quads and images, rotated gradient, rotated quad clipped in a group) and passes on all six surface variants, with the 11 new cases differing from the oracle by at most 1/255; `tiers` (baseline, bindless, enhanced barriers, both) and `debug_layer` (GPU-based validation) pass with the new cases; `aqua/tests/render_slug.rs` (scaled and rotated text through the host lowering on both devices: curve ink within 12% of atlas ink, 15% for rotated text, no ink in the old bounding-box corners) and `lowering::rotated_quads_are_rotated_exactly_and_not_reported_as_approximated` pass. On Linux the oracle's own tests (`aqua-gpu-ref/tests/transforms.rs`: quarter turn equals the swapped rectangle, shear and rotation preserve area, scale multiplies it, ring ink within 6% of its analytic area at several scales and placements, the glyph alpha equals `linear_blend_alpha_over`) and `aqua-text/tests/slug_store.rs` (packed buffers evaluate identically to the CPU glyph, upload sequence) pass. Round 5 gave the store an eviction policy (14.T). Not done: Slug for vector paths and icons, anisotropic pixels per em, and a host-level check of the backdrop estimate on a real screen (the Editor was not run in this round).

### 14.T Text stack closure (decided 2026-11-04, round 5; `aqua-text::slug`, `aqua-text::raster`, `aqua-text::svg`, `aqua-oracle-dwrite`)
- **Color glyph placement.** `aqua-oracle-dwrite::Oracle::color_layers` renders COLR layers through `IDWriteFactory4::TranslateColorGlyphRun` and glyph-run analysis at a fractional baseline origin. `tests/color_diff.rs` compares Segoe UI Emoji (3 emoji, 16, 24, 32 and 48 px, 4 horizontal phases, 48 placements) by alpha centroid: ink ratio 1.01 for every policy; mean centroid error 0.40 px (worst 0.87) when the bin-0 bitmap is placed at the floor of the quantized position (what round 4 did), 0.27 px (worst 0.71) when the same bitmap is placed at the nearest whole pixel, 0.08 px (worst 0.23) with a bitmap per horizontal bin. Decision: keep whole-pixel color glyphs (four bins would quadruple the RGBA atlas for 0.19 px) and place them at the nearest pixel: `GlyphPlacement::color_x` is `x + 1` for bins 2 and 3, and `GlyphResolver::lower` uses it. `aqua::render::lower` applies the same rule inline (`pixel_x + 1` when the subpixel bin is 2 or 3) for its `GlyphSlot::Color` branch, so both paths place color glyphs identically (checked in round 6). DirectWrite renders CBDT and sbix only through Direct2D, so this comparison covers COLR; bitmap strikes are compared by size and origin (below).
- **sbix.** DirectWrite reads the synthetic sbix font (`GetGlyphImageFormats` reports PNG; `GetGlyphImageData` returns the strike at the requested ppem with pixel size 16x16 and horizontal left origin (-1, 14)), and Aqua's rasterizer yields the same size with `left = 1`, `top = 14` for strike origin (1, -2) at ppem 16 and the equivalent at ppem 64 (origin (4, -8)); a 24 px request scales from the nearest strike to 24x24 with the quadrant colors in place, and a glyph without sbix data has no color image. This replaces the synthetic-PNG unit test as the sbix evidence; a real Apple font remains unavailable.
- **Slug store eviction.** `SlugStore<K>` (key `SlugKey` in production) is an arena of variable-size glyph records with a free list. The budget is `STORE_BUDGET_BYTES` = 4 MiB of texels (262,144 texels, 256 rows of the 1024-wide texture; about 350 to 700 glyphs), a share of the 9 MiB cache figure of section 11 that Slug text can never exceed in steady state. Each `lookup` stamps the entry with the current epoch; `uploads()` (called once per lowered frame) ends the epoch. When a new glyph does not fit under the budget, entries are evicted least recently used first, never one stamped with the current epoch (the frame being built still reads them), until a free block fits; if every entry is in use the store grows past the budget and counts an overrun (`overruns()`), and the next frame's lookups bring it back. Freed blocks coalesce and the tail is truncated; evicted glyphs are removed from the map so a later lookup repacks them. Uploads write only the rows that changed (dirty range); the texture is recreated when it must grow or when the live rows fall to a quarter of the allocation (`resident_bytes` follows). Indices handed out in a frame stay valid for that frame because eviction never moves a block. Tested in `tests/slug_store.rs` (LRU order, current-frame protection, overrun counting, row-only writes, shrinking).
- **SVG text.** See 14.E. Host-level evidence: `aqua/tests/images_svg_text.rs` decodes an SVG with a `<style>` sheet and an `em` size through `ImageAssets` with `set_fonts` on the decode worker, uploads it through `ManagedUiApp`, and paints it with the reference renderer and every hardware D3D12 adapter (red ink in the painted frame); without `set_fonts` the same document produces no ink. `aqua-text/tests/svg.rs` covers sheets, `em` and percent sizes, straight and curved `textPath`, `startOffset` and anchors on Windows; `svg_sheet.rs`, `svg_length.rs` and `svg_path.rs` run on Linux.

### 14.S Frame profiler and spike recorder (decided 2026-11-04, round 6; `aqua-protocol::probe`, `aqua::profile`)

Attribution of frame spikes needs per-phase times inside pure crates that may not read a clock. Decision: `aqua-protocol::probe` defines `Phase` (input, reactive, build, layout, text, lower, upload, plan, record, submit, present, wait), `Metric` (layouts, nodes measured, text runs shaped, scene ops emitted, upload bytes, passes, transient bytes, PSO compiled/loaded, atlas growth and the rest) and an install-once `fn(Event)` sink behind a `OnceLock`. Pure crates and adapters call `probe::span(Phase)` and `probe::count(Metric, n)`; with no sink installed each call is one failed atomic load. The host installs the sink only when `AQUA_PROFILE=1`. `aqua::profile` implements it: a per-thread recorder charges time and heap counters to the innermost open phase (exclusive times), `begin_frame`/`end_frame` close an app-thread frame in `Aqua::draw_ready` and a render-thread frame in `Slot::run`, a per-second summary line (`aqua-profile role=... work p50/p90/p99/max, frames over 4, 8.3 and 16.7 ms, allocations per frame, per-phase maxima`) is printed for each role, and every frame whose work (everything but `wait`) is at least `AQUA_PROFILE_SPIKE_MS` (default 4) prints an `aqua-spike` line with the phase breakdown, per-phase allocation count and bytes, the non-zero metrics, the rebuild reason (`FrameReason` bits) or render cause (arrived, forced, trim, repaint), the dominant phase and any unattributed wall time. `AQUA_PROFILE_OUT=path` appends to a file instead of stderr. Heap counters come from the `profile-alloc` cargo feature of `aqua` (a thread-local counting `GlobalAlloc`, off by default so release builds without it pay nothing; the Editor port exposes it as `profile-heap`). Not done: ETW (`wpr.exe`) capture, D3D12 internal split of `record` into command recording and queue submission, transient-heap reallocation as a counter.

### 14.15 Host composition root (2026-11-04, `crates/aqua`)

aqua is the only event loop. `native::looping::Host` implements the `aqua-shell-win32` `Handler` and drives `Aqua`, which steps the single-window `aqua_runtime::Runtime` Machine with time as an input (`Tick`, `Frame { window, presentation }`) and executes every `RuntimeOutput` in `apply_output` (shell, IME, access tree, render commands, `wake_at`, clipboard feedback). The `Application` trait remains as the compatibility layer for the Editor port, extended with `step_input`, `take_output`, `on_dialog`, `on_motion_event` and `motion_commands`. winit is gone from the runtime; an `Inbox` (mutex queue of `AquaUserEvent` plus the shell `Waker`) replaces the event-loop proxy. Window creation order: hidden shell window, UIA attach, `TsfIme::from_hwnd`, show, render link. One render service thread for all windows (record 14.N); the D3D12 `WindowBackend` is not `Send`, so `RenderLink` ships an `InitFactory` and the backend is built lazily on the service thread. Pacing: a slot waits on its waitable swapchain slot each time it runs and, when its previous iteration did not present, may not run again for one frame interval (`not_before`), so an idle or failing present cannot busy-loop and one window never sleeps for another. `Presented` and motion events return to the Machine as `GpuEvent::Presented` and `RenderEvent`. Lowering of the display-item scene to `PaintCommand`s lives in `crates/aqua/src/render/lower.rs` (rects, quads, shadows, clips, opacity, blur, scale and translate transforms, glyphs through `GlyphResolver` and `Residency`, retained images and vectors); images reach the render thread over an `ExternalUpdate` side channel. A full command ring drops a command, so `RenderLink` keeps a backlog and retries. Snapshot transitions and text raster mode are implemented in the lowering (10.6). Not supported and reported as `WindowError::Unsupported` or counted in `LowerReport.skipped`: rounded clip radius, inset shadows, dashed borders, general transforms, GPUI items. Not built: caption hover forwarding, image and file clipboard payloads. `FrameReport::gpu_time` is filled by the backend but the host does not yet surface it. The host depends on neither `aqua-platform` nor `aqua-render` (both are deleted; image decode lives in `aqua-media::decode`), and no manifest names `winit` or `wgpu`.

**14.E SVG text.** Decision (revised in round 4): `aqua-media` builds `resvg` with only `svgz` and `raster-images`, so `usvg` has no `text` feature and no `fontdb`, `rustybuzz` or second text stack enters the lockfile. SVG `<text>` is rendered through `aqua-text` instead: `aqua_text::svg::outline_text(bytes, &mut FontManager)` parses the document with `roxmltree`, lays out every top-level `<text>` (with `<tspan>` children) through `TextLayout` (shaping, bidi, per-glyph fallback), converts each glyph to an em-space outline (`slug::em_outline`, skrifa, unhinted, variable axes and synthetic italic applied) and splices a `<path>` in place of the element, so ancestor transforms, opacity and inherited paint still apply. It returns the input unchanged (`Cow::Borrowed`) when there is no `<text>` or the document does not parse, leaving the error to resvg. Supported: `x`, `y`, `dx`, `dy` (first value of each list), `font-family` (generic names and quoted names), `font-size` (px), `font-weight`, `font-style`, `letter-spacing`, `text-anchor` per absolute-positioned chunk, `fill`, `stroke`, `opacity` and their opacity variants per `<tspan>`, properties inherited from ancestors and from inline `style`. Round 5 added `<style>` sheets (type, class, id and universal selectors, compound and descendant selectors, comma lists, specificity then source order, inline `style` over sheets over presentation attributes, `@` rules skipped), `em`, `ex`, `rem`, `%`, `pt`, `pc`, `in`, `cm`, `mm` lengths and the keyword sizes for `font-size` (resolved down the ancestor chain), `em` for `x`, `y`, `dx`, `dy` and `letter-spacing`, and `<textPath>` (`href` or `xlink:href` to a `<path>`, `startOffset` as length or percent, `text-anchor`, `<tspan>` inside; glyphs sit on the path by their advance midpoint, rotated by the tangent of a flattened path with arcs, cubics and quadratics). Still not supported, by decision: per-character `rotate` and `textLength`, `writing-mode`, percent `x`/`y` (they need the viewport), a `transform` on the referenced path, `>` and attribute selectors, color glyphs (emoji outlines are skipped) and fake bold; unsupported constructs render without that effect and never fail the decode. The host runs it on the image decode worker (`ImageAssets::set_fonts`, set by `App`) under the shared font lock, and decoding without fonts renders no text. Enforced by `aqua-verify/tests/banned.rs`, which bans `wgpu`, `glyphon`, `cosmic-text`, `winit`, `accesskit_winit` and `fontdb` in every manifest, in `Cargo.lock` and in source. Verified on Windows (`aqua-text/tests/svg.rs`: Arial text becomes paths that resvg paints, start, middle and end anchors place the ink around the anchor, tspans keep their own fill).

14.Q **Host lowering and text path (decided 2026-11-04, `crates/aqua/src/render`, `aqua-transport`):** the host draws only through `aqua_transport::GpuRenderHost`; `render::host::GpuFrames` is a thin wrapper that adopts the caller's surface and keeps `RenderStats` for the frame-stats line. `aqua_transport::Lowering` now takes a `LowerContext { size, scale, now }` and has hooks: `sync` (drains the `ExternalUpdate` channel on the render thread), `device_recovered`, `trim`; the host feeds `FrameReport::gpu_time` into `FrameRecord::gpu_micros` and into `TrimPolicy` (`aqua_transport::trim`, a pure state machine: every 300 frames, never on a frame that uploaded or whose max(cpu, gpu) time exceeded half the frame budget, entries unused for 1800 frames; `TrimHandle::request` forces `TrimRequest::Everything`, exposed to the runtime as `RenderLink::request_trim`). `FrameRecord` also carries `approximated_items`, `glyphs` and `trimmed_entries`, and the inspector JSON prints them. Surface extents use `round`, not `ceil`, so a physical size survives a logical round trip. After `recover()` the host keeps adopted surfaces when the backend reports rebuilt surfaces.

   `render::lower::Lowering` lowers every `DisplayItem` variant; the only things it counts as unsupported are real failures (`VectorFailed`, `PathFailed`, `MeshTooLarge`, `MeshFailed`, `GlyphBudget`, `UnbalancedScope`). Items that reference a text run or image layer the render thread has not received yet count as `pending` (the app and the render thread share no ordering between the scene ring and the external-image channel) and are not unsupported. Decompositions, all in pure `shape.rs`: per-corner radii draw one full-size quad per distinct corner clipped to quadrant (or half) rectangles whose seams are snapped to whole pixels; uneven borders draw one ring clipped to each side strip; dashed borders draw the ring clipped to corner squares and 2/3-duty dashes (period 3 x width, evenly distributed, at most 256 per side); inset shadows (native and GPUI) are four outer half-plane shadows over the shadow hole composited with ordinary over (1 - gx*gy = a + b - ab holds exactly), inside a rounded clip; outer shadows with mixed radii use the same corner pieces with the clips extended outward by the blur reach. Transforms are a full 2D affine (`affine.rs`): rects map to their bounding box, glyphs and points map exactly, radii and sizes scale by sqrt(|det|); this is exact for translation, scale and quarter turns and counted in `approximated_items` otherwise (no pass can rotate an instance). Rounded clips use `PushRoundedClip` when the radius is at least 0.75 px and the clip covers at most 75% of the surface; larger ones fall back to a rectangle and count as approximated, because a rounded clip is a bounded layer. GPUI items map as follows: `GpuiBackground` to `Paint::Solid`/`Gradient` (CSS angle axis), `GpuiBorder` to border rings, `GpuiShadow` as above, `PushGpuiContentMask` to a pixel-outward rectangular clip, quad pulses to an alpha factor from the render-side `Cycle::Pulse` for the pulse's scene item (14.N), text colour/source colour/opacity ranges/colour maps/shimmer as a `TextStack` resolved per glyph (shimmer phase from `ShimmerClocks`, driven by `LowerContext::now`), `GpuiSvg`/`GpuiTransformedSvg` through `Residency::vector` (rotation by wrapping the SVG in a rotated `<g>`, quantized to 3 degrees), `GpuiPath` by converting the commands to a `Drawing` cached by content with the integer part of the position removed (`vector.rs`), and `GpuiMesh` by a CPU triangle rasterizer (`mesh.rs`, z-buffer, the old key/fill/rim lighting, barycentric edge lines) cached as an image per mesh id, style and size, up to 400,000 triangles. Text uses `GlyphResolver::resolve` per glyph (not `GlyphResolver::lower`, which cannot apply the device scale, per-glyph colour or the affine) with `place_glyph`'s rounding rules.

   Recovery: `RecoverySignal` connects `WindowBackend::set_recovery_listener` to `Lowering::device_recovered`; the listener marks textures lost when the notice says `HostMustReupload`, and the lowering then rebuilds `Residency` and the glyph resolver (the atlas re-creates its pages on the next frame; there is no separate `PageTable` in this path); with `Replayed` textures the atlas is kept; a backend without a listener is treated as having lost everything. Startup (`native/d3d12.rs`): the pipeline library is read from `%LOCALAPPDATA%\aqua\pipelines.cache` and written back by the maintenance hook (every 900 frames and on drop) when its fingerprint changed; the fallback index is loaded, the prewarm worker (`persist::spawn_prewarm`, sans-serif 400/500/600/700 and monospace 400/700) runs once per process and writes the index when done, and the hook writes it again when it changed. Verified on Windows (RX 9070 XT, hardware and WARP offscreen painters; `tests/render.rs` 45 tests and `tests/render_window.rs`: windowed `WindowBackend` through `GpuRenderHost`, GPU timestamps in the record, injected device removal with texture re-upload, pipeline cache round trip, prewarm). Round 6 closes two of the unverified items: rotated and skewed content is checked on D3D12 by pixel (`tests/host_motion.rs`, `rotated_and_skewed_boxes_land_on_their_transformed_footprint_on_d3d12`: a 45 degree box, a skewed box and a quarter turn, inside and outside samples, WARP and the discrete adapter) and in a real swapchain window (`tests/host_swapchain.rs`, below). Still not verified: pulses and shimmer without a frame trigger, 3D meshes against the old shader, and the `PushGpuiContentMask` plus rounded-clip interaction on large windows.

**14.N Render service, shared device, damage, composition, trim and repaint wake (2026-11-04, round 4, `crates/aqua/src/render`, `native/d3d12.rs`).** Decisions:

1. One render thread for every window. `render::service::RenderService` owns a `Slot` per window (its command ring, event ring, `RenderSide`, `FrameTarget`, clock and `RenderStats`); `RenderLink::spawn` hands a slot over and `RenderLink::shutdown` takes the `RenderSide` back. The thread waits on one condition variable that every command ring, every `RenderLink::external` and `request_trim` raise, and otherwise sleeps until the earliest `RenderWake::At` or pending-repaint deadline, so an idle process runs no timer. A slot runs when it has commands, feedback, a due wake, an external arrival, a trim request or a due repaint, waits on its own swapchain slot, steps its `RenderSide` and executes.
2. One device. `native/d3d12.rs` keeps a thread-local `Weak<Hub>`; the first window builds the `WindowBackend` (pipeline cache, text services), later windows join it, and the last window to close drops it (device memory is returned). Each window holds a `WindowHandle` that implements `GpuBackend` over `Rc<RefCell<WindowBackend>>`. Texture handles are `page.index * 2 + kind` per window, so a handle collides across windows; `render::namespace` ORs a window's namespace into bits 24 and up of every handle in uploads and plans (namespace 0, the first window, is unchanged and pays nothing). Recovery: the window that notices the loss calls `WindowBackend::recover`; every other handle sees the changed `generation` on its next `upload`, `execute` or `present`, fails that call once with `DeviceFailure` (so its host marks itself lost) and adopts the recovery in its own `recover`, which resets its lowering when textures must be re-uploaded. The one recovery listener fans out to every window's `RecoverySignal`.
3. Damage. `render::damage::DamagePlanner` builds `Footprints` of the render-side scene each frame (text ink from the laid-out size of the run, padded by 6 px plus 15% of its height for overhang), diffs them against the last presented frame with `DamageTracker::record_scene_diff`, pads each region by a pixel, coalesces to 8 regions and passes them to `WindowBackend::execute_damaged` and `present_with_damage` (the backend does the per-buffer age accumulation). It answers Full on the first frame, on a viewport or scale change, after a frame that did not present cleanly (`invalidate`), and when any damage touches a blur zone; pulses and shimmers contribute only their own footprints (14.N); an unchanged scene damages a single pixel. The baseline advances only after a `Presented` frame. Checked against the oracle: `tests/damage.rs` renders random scenes (rects with shadows, translated groups, removals) on `aqua-gpu-ref` at scale 1.0 and 1.25 and requires that the previous image with only the damaged regions replaced equals the full render.
4. Repaint without a scene change. `FrameTarget::repaint` reports `Animating` while the scene pulses or shimmers (one repaint per `ANIMATION_PERIOD`, silent), `NextFrame` during a snapshot transition (every vblank, reported), and `Poll(33 ms)` while lowering skipped an item whose image or text run had not arrived (at most 60 polls, then it waits for the next scene change or arrival). `RenderLink::external` also raises `RenderStats::arrivals`, which forces one full repaint. A forced frame re-presents the last frame id. Round 6: its `Presented` feedback is reported (it was dropped before, so an animation that ran only on repaint frames, a shimmer or a snapshot transition, never reached `on_frame_completed`); only a trim frame stays silent. The consequence is that `on_frame_completed` can receive the same sequence number more than once, once per presented repaint, and `Aqua` counts every one in `frames_presented`; applications key on `sequence >= last`, not `>`. `tests/render_service.rs` asserts 13 `Presented` events for 12 repaints plus the scene frame and 2 for a scene frame plus one arrival repaint.
5. Composition. A window whose clear colour is transparent (`Config::resolve` forces this for Mica, Mica Alt and Acrylic) gets `WindowBackend::create_composition_surface`; its swapchain content crosses to the UI thread as a `Box<dyn Any + Send>` through `CompositionSink`, `Aqua` attaches it in `drain_render_events` with `NativeWindow::attach_composition` (shell composition state is thread-local to the UI thread), and the target hands the content over again whenever the window handle's recovery generation changes.
6. Trim. `Aqua::request_trim` runs on `WindowEvent::Occluded(true)` (the shell reports minimize as occlusion) and `request_trim_all` on the rising edge of the Windows low-memory resource notification, polled at most every 2 s when the host pumps events or produces a frame (no timer). The slot runs a forced frame so `TrimPolicy` executes `TrimRequest::Everything` on the window's residency. Round 5: the shell reports occlusion by other windows (`aqua-shell-win32::occlusion`, `ShellEvent::Covered`, z-order walk with `DWMWA_EXTENDED_FRAME_BOUNDS`, cloaked and partial-overlap aware; `AQUA_RENDER_WHEN_COVERED=1` ignores it) next to minimize, and the host treats either as `Occluded`. `MemoryPressure` reads the notification through `WaitForSingleObject(handle, 0)`, the same path for the OS `CreateMemoryResourceNotification(LowMemoryResourceNotification)` handle and for a handle installed with `watch_notification`, so a test drives it with a manual-reset event; the OS notification itself cannot be raised without exhausting physical memory and was not. An occluded window builds no frame and pushes nothing to the render side, except that it still builds the scene for the accessibility tree while an access sink (UIA client or inspector) needs snapshots, and it then requests no animation deadline, so a covered window with a screen reader is never an empty tree. Round 6: the window backend's `set_visibility`, `service_budget` and `trim` are called by the host (11.3).

Verified on Windows (RX 9070 XT, debug build): `tests/render_shared.rs` runs three real windows (one transparent) on one service thread and one device (`device_sharers == 3`), animates one quad in each, and finds 97 to 103 partial frames and 1 full frame per window with an average of about 2,160 damaged pixels per partial frame, executes a trim request on every window, injects a device loss and sees all three windows keep presenting and the composition surface re-attached. `tests/render_service.rs` (6 tests, no GPU) covers sharing, idle quiet, pending polling, continuous repaint, arrival repaint, trim and closing one window. `tests/render.rs` (45) and `tests/render_window.rs` pass unchanged; `host_windows` passes. The `host_native` stall was root-caused in round 5 and is not in device creation: traces showed `Occluded(true)` from the shell before the first frame (another window, often another agent's test window at the default cascade position, fully covered the new window), `produce_frame` returned early for an occluded window, so no scene, no access tree and no inspector tree existed until the UIA client activated the window and uncovered it. Fixes: a covered window still builds the access tree while a sink needs it (above), `host_native` no longer depends on desktop state, `windows_desktop` sets `AQUA_RENDER_WHEN_COVERED=1` because it asserts `build_scene` runs for its main window (its own child window covers the main one), and `host_trim` raises its two windows to the top of the topmost group and drives its phases from a mailbox wake instead of frame completions (a covered window completes none). ### 14.U Shape cache, Slug warm-up and lock-free glyph lookup (decided 2026-11-04, round 6; `aqua-text::shape_cache`, `aqua-text::slug`, `aqua-text::residency`, `aqua-core::hash`, `aqua::render::lower`)

Evidence (release, Windows, `aqua-text/tests/shape_atlas_probe.rs`, 400 markdown-like blocks of about 330 characters with regular, bold and monospace spans, 12 blocks on screen, one frame per block of scroll):

| Measurement | Before | After |
|---|---|---|
| Fresh `TextLayout` of unchanged text at another width (what the runtime and the measure path do on every resize or remint), per block | 77 us (every paragraph re-shaped) | 48 us (no shaping; the remainder is line breaking and glyph placement) |
| Mask-atlas lowering of 12 visible blocks, steady frame p50 | 0.357 ms | 0.161 ms (hashing) |
| Slug lowering of 12 visible blocks, p50 | 0.157 ms | 0.069 ms (hashing and warm store) |
| Slug store growth events during the scroll | 1 at frame 0 (the store grows on every new glyph that overflows its 8 rows) | 1 at frame 0 (the whole printable ASCII range of each face is resident after its first glyph, 285 glyphs, 0.5 MiB) and none afterwards |
| Streaming one token into a 1.6 KB paragraph, full relayout, p50 / p99 | 0.122 / 0.263 ms | 0.078 / 0.158 ms |
| Streaming one token into a 120-line code block (one text node, one paragraph per line), p50 / p99 | 0.252 / 0.309 ms | 0.169 / 0.265 ms |

Decisions:

- **Persistent paragraph shape cache** in `FontManager` (`shape_cache.rs`). `ShapedParagraph` is shared as an `Arc`; the key is a 128-bit digest of the paragraph text, its absolute start, the clipped spans that overlap it (range, `TextStyle::shaping_hash`, inline cell width), the scale, the line-height and inline-cell flags and the font revision. Colors, underline and background are applied after shaping, so they are not in the key. Two generations of at most 4 MiB each (`SHAPE_CACHE_BUDGET_BYTES`), promoted on hit, cleared on a font-set change. Because the runtime builds a new `TextLayout` on every width change and the measure path builds another for the same string, both now hit; appending to a text node shapes only the changed paragraph. Counters: `FontManager::shape_cache_stats()`, printed as `aqua-text-stats` by the host.
- **Layout fast paths.** `build_display` no longer walks grapheme clusters when no mask is set (a newline is always a standalone grapheme unless it follows a carriage return, so concatenation, or a newline-to-space swap in single-line mode, is identical; a test compares both against `unicode-segmentation`). The `InputKey` style key is a 128-bit digest of the span styles instead of a formatted string.
- **Warm-up.** `SlugStore::lookup` makes the printable ASCII range of a face resident the first time any glyph of that face is requested, in the same frame, so the store texture is created once at its final size and later glyphs of that range never upload. Glyphs outside ASCII still upload on first use (one dirty-row write, no texture re-creation unless the pow2 row count overflows). The 8-bit mask atlas (used only when `outline_text` is off) keeps on-demand rasterization; its first shared page is 512 (was 256) so the first 400 distinct glyph variants do not grow it. Warming the mask atlas for four subpixel bins per size was not done: the Editor defaults to outline text, and the mask path would pay 380 rasterizations on first sight of each size.
- **Lock-free resident lookups.** `SharedFonts` mirrors the font revision in an atomic. The lowering takes the font mutex only when a glyph is not resident (`SlugStore::resident`, `GlyphResolver::resolve_shared`); the render thread no longer blocks behind a UI-thread shaping call for text it already has.
- **Fast hashing.** Atlas entries, Slug store and cache, face interning and the shape cache use `aqua_media::hash::FastMap` (multiply-rotate hasher) instead of SipHash; the keys are internal.
- **Counters for the spike recorder.** `LowerReport` carries `atlas_created`, `atlas_upload_bytes`, `glyph_rasterized`, `slug_created` and `slug_upload_bytes` per frame; `RenderStats` accumulates them and `aqua-text-stats` prints them. `aqua/tests/text_steady_scroll.rs` gates zero growth, zero rasterization and zero upload bytes while scrolling through ASCII text in outline mode.

### 14.V Keystroke latency path (decided 2026-11-04, round 6; `aqua::latency`, `aqua::runtime`, `aqua::native`, `tools/key-latency.sh`)

Measurement. `AQUA_INPUT_LATENCY=1|2` stamps every keystroke (key down, text input, IME events) at host entry and reports, per presented frame, the phases input, queue (end of input dispatch to frame start), build, handoff (scene queued to render thread pickup), GPU wait (frame-latency waitable) and the total up to the render thread's present call; `2` prints every sample, `1` one summary per 40 samples. The render thread counts the scene commands it applies (`RenderStats::scenes_applied`, `scenes_presented`) so a keystroke is matched to the frame that carries its scene, not to the next frame. `tools/key-latency.sh aqua|gpui [keys|open]` runs the same scripted typing against the private bench Forge for both Editors: `win-drive.ps1` posts WM_KEYDOWN/WM_KEYUP (the host's own `TranslateMessage` produces the characters) with a precise system-time stamp per key, an ETW session on `Microsoft-Windows-DXGI` records the owning process's `Present` start/stop events, and `tools/key-latency-report.py` pairs each key with the first `Present` return after it. Elevated tracing (`wpr`) is refused without administrator rights; user-level `logman` sessions work and are what the tool uses. The figure is the Present call return, not scan-out: Aqua's Present never blocks (frame latency 1), so add up to one refresh period (6.06 ms at the measured 165 Hz) for photon time; GPUI paces on display ticks, its Present return is quantised to the display state and swung between 4 and 18 ms in this setup.

Findings (release, 2560x1440, large bench thread, composer typing, 8 interleaved runs):

| Phase per keystroke before | Value |
|---|---|
| Whole-view rebuild per keystroke (`rebuilds` 16 per s at 9 keys per s, reason `shell_updates`) | 3.6 ms rebuild plus 7 to 11 ms layout visiting 18.7k nodes |
| Input dispatch of the text event | 4 to 8 ms (mostly the rebuild) |
| Present-return latency p50 / p90 / p99 / max | 23.6 / 27.8 / 32.7 / 58.8 ms |

Causes and fixes:

- The composer's change detection (`ComposerVisible`) compared the editor text and selection, so every keystroke rebuilt the whole Editor view although the editor node already receives its text through `UiCommand::EditText` in the same input event. Typed events (`EditorEvent::Changed`, `SelectionChanged`, `PresentationChanged`) now compare chrome only (empty and blank flags, disabled, limit notice, suggestion, tokens, picker, mention, questionnaire, attachments); programmatic edits keep the full comparison and `drain_async` rebuilds only when the editor revision moved inside the drain. Rebuilds during typing went from 16 per second to 0.
- A message consumed by the TSF hook never reached the loop's queue, so IME text waited for the next unrelated tick. A consumed message now queues a `Wake` (`aqua-shell-win32::looping`).
- `Host::tick` drained the inbox (3 ms `on_wake` work in the Editor) before drawing; it now drains IME text and draws input frames first (`Aqua::drain_text`, `draw_input_frames`), then pumps the inbox and draws the rest.
- The process opts out of execution-speed power throttling and ignores the timer-resolution policy, and the render service and UI thread run at above-normal priority (`native::priority`), because background windows were woken about 1.4 ms late.

Result: Aqua present-return p50 4.6 to 5.5 ms, p90 5.5 to 6.9, p99 7.8 to 9.8, max 8 to 11 ms (three runs, 150 keys each), no key over 16.7 ms; GPUI p50 18.0 to 18.4, p99 21.5 to 24 ms in the same display state and 4 to 5.5 ms p50 in the low-latency display state; the p99 target of 12 ms is met in 7 of 8 runs (one run under heavy parallel build load measured p99 32 ms).

Open decisions closed: the Present return is the keystroke-to-present stamp for both Editors (above); typing is measured in a scratch window against the private bench Forge only.

Thread open (bench thread, 3 runs): fetch of the tail page 11 ms, fold 0.03 ms, apply 0.04 ms; first scene 41 to 54 ms after open (cold shaping of the first rows), first present 100 to 114 ms, then six more frames of 15 to 40 ms layout while the work spans and older pages arrive. The Forge's first-paint read acknowledgement arrives 548 ms after open (736 to 756 ms after the driver's click, GPUI 250 to 272 ms) because the Editor port withholds it until every visible reveal is settled (`reveals.pending` and `reveals.changed` must both be false), which takes four frame round trips of layout-bound frames. The remaining open gap is layout cost per rebuild (14.5 to 36 ms), not fetch or fold.

### 14.W Heap attribution, allocator choice and idle trim (decided 2026-11-04, round 6; `aqua::mem_probe`, `aqua-transport::trim`, `aqua-ui::tree::interaction`, `tools/heap-attribution.sh`)

Decisions, each backed by the measurements in section 11.4. (1) Heap attribution is done with the in-process stack-hash allocator plus offline symbolization; in-process symbolization of a 180 MB executable never finished and is not used. (2) The system allocator stays: mimalloc cost +76 to +80 MiB private and the segment heap gained nothing. (6) Not decided and still open: the 100 MiB private target. The user-mode driver's write-combined private memory (47.7 MiB picker, 62.8 MiB thread view) is the largest single item and belongs to the GPU backend; Aqua's own controllable share is Rust heap 25 MiB plus fragmentation 15 MiB.

### 14.RS Resize responsiveness (decided 2026-11-04, round 7; `aqua-runtime::scheduler`, `aqua-core::checkpoint`, `aqua-shell-win32::looping`, `aqua::native::looping`, `aqua::runtime`)

Evidence. The scoreboard resize probe is `SetWindowPos` followed by a `WM_NULL` `SendMessageTimeout`, so it measures how long the UI thread stays deaf to sent messages. Release port, fixture, 120 resizes: p50 38 to 77 ms, p99 79 to 158 ms (machine shared with other jobs). Per resize the UI thread ran a full view rebuild inside the `Resized` dispatch (2.1 to 4.5 ms), then a frame of 9 to 15 ms with roughly 70% in two taffy passes plus row realisation (the width-sensitive transcript collection rebuilds its rows on a width change), then a second frame for the `WM_PAINT` that the resize itself invalidated. Backend and render-thread work was under 4 ms and not the cause.

Decisions. (1) The shell swallows the first `WM_PAINT` after a `WM_SIZE`; the resize already requests a frame. (2) The host holds `Resized` events per window and dispatches the latest one once per frame, flushing earlier only for events that must see the new size (clicks, keys, focus, scale); coalescible pointer input and window bookkeeping events do not flush. (3) After a frame whose reasons contain `RESIZE`, the scheduler gates the next `RESIZE` frame for 1.5 times the frame's cost (cost capped at 30 ms), which bounds the UI thread duty cycle during a continuous resize to 40%; other reasons are not gated and the final size always gets its frame. (4) `aqua_core::checkpoint::reach()` is a cooperative yield point: the Win32 host installs `pump_sent_messages`, a rate-limited (300 us) `PeekMessage(PM_NOREMOVE | PM_QS_SENDMESSAGE)` that answers sent messages from long frames; the window procedure only enqueues events, so it is safe to run mid-frame. Checkpoints sit between the layout passes, per row factory call, per taffy leaf measure, between frame phases and inside the Editor port's rebuild.

Measured (release, fixture, same harness, noisy shared machine): p50 3.1 ms, p90 5.2 ms, p99 7.6 ms, max 7.7 ms for the port against GPUI p50 2.9 ms, p99 8.9 ms in the adjacent run; three further alternating pairs ranged 2.1 to 4.8 ms (port) and 3.0 to 7.5 ms (GPUI) at p50 because of external load. The final frame after the resize loop shows the full window at the final size. Windows tests that exercise the loop (host_full 5/5, host_window 3/3, host_windows, host_counters, collections_conformance, facade_pump, perf_scene) pass.

Open: p50 is at the harness floor, so beating GPUI needs a quiet machine and repeated pairs; the width-sensitive collection still rebuilds every resident row on a width change (about 5 ms uncontended), and the Editor view is rebuilt in full on every dispatched resize.

### 14.SC Render-thread planning cost (decided 2026-11-04, round 7; `aqua-graph::graph`, `aqua-graph::paint`, `aqua::render::lower`, `aqua::render::damage`, `aqua-scene::footprint`, `aqua-core::hash`)

### 14.ST Streaming rebuild path (decided 2026-11-05, round 7; `editor-aqua::conversation::view::factory`, `aqua-ui::element`, `aqua-ui::tree`, `aqua-text::layout`)

Evidence. On the fixture stream scenario every streamed prose row failed to build ("current live source is unavailable", 722 errors in one 24 s run, no screenshot ever showed the reply): the fixture streams by upserting a running `AssistantMessage` with a growing `Inline` text and no `Live` events, and the factory demanded a live binding for any running prose row. A failed build leaves the previous tree mounted and retries on the next frame, so the old streaming CPU numbers measured an error loop. The profiled success path (release, fixture, `AQUA_PROFILE=1`, per second at 31 events/s): `Tree::refresh` of the whole view 28 to 52 ms, layout 74 to 109 ms (three tree layouts and three collection realizations per frame), text layout 12 ms of which shaping 8 ms, 500 to 1000 nodes measured per frame.

Decisions. (1) A running prose row with `Inline` text and no live binding renders from the item text; with a binding it still requires the captured binding to match the row snapshot, and a running row with `Stored` text and no binding is still an error. (2) `Element::refresh_text` re-syncs the measure leaf only when its display text, font size, style or spans changed (`sync_text_leaf_if_changed`); it used to reset the leaf and mark layout dirty for every text node on every refresh, so each whole-view rebuild re-measured every label. (3) `UiTree::sync_children` returns early when the reconciled child list equals the retained one; it used to relink the taffy children and mark the parent and all its ancestors dirty on every call. (4) `aqua-text::TextLayout` keeps a placed-paragraph cache keyed by the shaped paragraph identity: line breaking, line placement and the glyph rows of a paragraph are reused while its wrap width, alignment, container width and span colours are unchanged, so streaming into the last paragraph only re-places that paragraph. (5) The rebuild spans (`rb_build`, `rb_refresh`, `rb_mounted`, `rb_total`, `conv_rebuild`, `f_realize`, `f_md_prepare`, `f_md_project`, `on_wake`, `on_fc`, `shell_drain`) are recorded by `shell::rebuild_stats` when `AQUA_REBUILD_STATS` or `AQUA_PROFILE=1` is set and printed once a second with the rebuild reasons.

Measured (release, fixture stream, six interleaved pairs, process CPU from `stream0` to `stream2`, noisy shared machine): with decision 1 and 4 only median 20.4 % of one core, with decisions 1 to 4 median 16.3 %; GPUI release in the same harness 11.3 to 12.5 %. In the profiled run the refresh span fell from 0.75 to 0.45 ms per rebuild, the layout span from 74 to 109 ms/s to 66 to 71 ms/s and the median app frame from 2.7 to 3.3 ms to 1.3 ms.
